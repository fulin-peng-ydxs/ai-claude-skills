# 页面 UX 审查清单

审查时使用本清单。只报告影响可用性、一致性、清晰度、稳定性或造成不必要复杂度的问题。

## 1. 范围与证据

- 从路由、菜单、页面注册表、文件名、组件预览、文档中识别页面。
- 用户指定模块、路由、页面文件、PR 或 diff 时，严格按指定范围审查。
- 未重新指定范围时继承当前任务；独立审核且没有范围线索时覆盖可访问页面。
- 先读设计事实再评价页面：设计系统、布局模板、主题变量、组件目录、全局样式、高质量同类页面。
- 选择视口、终端、消费者与证据时读取 [前端验证规范](~/ai-agent-config/config/force/frontend-verification.md)，按其方法处理版本确认、证据缺口和联合审核去重。
- 对照原型时比较可比状态下的信息顺序、层级、间距、控件对齐与操作线索；响应式变化按设计意图判断。

## 2. 风格统一

按用户可观察的效果检查同角色一致性，保留有任务依据的差异；实现是否重复和是否违反契约分别交给复用与合规审核。

检查：

- 页面标题区、工具栏、筛选区、内容区、分页、空状态、弹窗、抽屉、标签页、表格、卡片、表单是否和同类页面一致。
- 同一含义的按钮是否使用一致的颜色、尺寸、图标风格、顺序、禁用态、加载态和危险态。
- 同排同角色控件在实际渲染中比较字号、字重、行高、高度、圆角、内边距和基线；源代码用了相同 class 仍可能被继承或媒体查询覆盖。不同角色可有明确层级，文字不同不必机械等宽。
- 表格是否使用一致的行高、表头样式、排序提示、对齐、空态、加载态、分页和操作列行为。
- 表单是否使用一致的 label 位置、宽度、间距、必填标记、placeholder、校验时机和错误位置。
- 状态标签、徽章、状态点、chip、风险标签、结果文字是否共享语义颜色和形态规则。
- 弹窗和抽屉是否共享宽度、标题层级、内容 padding、footer 布局、滚动行为和关闭行为。
- 空状态的语气、层级、恢复入口是否与同类任务一致。

定级：

- 严重风格不统一、同角色交互差异造成理解混乱：`P1`。
- 局部细节不一致但页面仍可理解：`P2`。
- 同时发现明确契约违规时关联合规问题，保留其定级，不用本节体验定级覆盖。
- 长期精致度问题：`P3`。

## 3. 布局与信息层级

检查：

- 首屏是否展示真实工作区或核心内容，而不是装饰、空白或大段说明。
- 用户是否不用读长文就能识别页面目的、主要内容、主操作和次操作。
- 相关控件和内容是否自然分组。
- 列、卡片、表单行、按钮、表头、操作区是否对齐稳定。
- 间距是否来自小规模尺度，不随机忽大忽小。
- 页面密度是否符合产品类型；管理、数据、研究、仪表盘、运营工具应紧凑、安静、可扫描。
- 滚动归属是否清楚，避免多个嵌套滚动区互相抢滚动。
- 固定区和滚动区是否有意设计；关键筛选、表头、分页、操作 footer 不应意外消失。
- 卡片是否只用于独立内容块，而不是装饰每一个页面 section。
- 避免卡片套卡片、边框过多、阴影过重、大面积无效空白和装饰容器。
- 加载、hover、切换 tab、筛选变化、刷新数据时，容器尺寸是否稳定。

## 4. 颜色与视觉语义

检查：

- 主色、次色、成功、警告、危险、禁用、选中、hover、focus 是否有稳定含义。
- 颜色是否与项目已确立的视觉角色一致；token 的实际消费方式由合规或复用审核判断。
- 文字和图标在常规、hover、选中、禁用、深浅主题下是否清楚可辨；分别检查文字对背景、图标内部符号对填充色的对比，不能因强调色鲜明就判可读。警告色取自项目语义约定，不自行规定黄色或橙色。
- 危险操作是否明确，但不在非当前任务中抢占注意力。
- 同一状态是否在不同页面使用同一颜色。
- 图表、徽章、标签、状态点是否必要时配合文字或形状，不只靠颜色传递关键信息。
- 渐变、强阴影、装饰背景、高饱和色块是否干扰工作内容。

## 5. 字体与可读性

检查：

- 页面标题、分区标题、正文、表格文字、标签、辅助说明、数字是否层级清楚。
- 运营和后台页面不使用 hero 级标题或营销式文案塞进紧凑面板。
- 长文本是否有明确处理：换行、省略、tooltip、popover、抽屉、详情页或列展开。
- 按钮文字、表头、标签、弹窗标题、字段 label 是否不溢出容器。
- 数字、日期、百分比、金额、数量、状态是否便于比较。
- 高密表格对齐是否一致；可比较数字列应统一对齐。
- 输入控件的边界、内部文字起点、辅助说明及错误文本是否按同一角色对齐；单行内容检查文字垂直中心，不能仅以外框居中作结论。数字输入与列表比较按任务确定对齐，不机械统一左右方向。
- 辅助说明是否短且靠近对应控件。

## 6. 交互直观性

检查：

- 布局或交互改造中，用同一用户任务比较前后入口可发现性、点击/展开层级、是否离开当前任务及返回后的草稿、选择和位置保留。记录增加或减少的实际负担及其任务依据，不把点击数越少机械当作越好。
- 核心操作是否因视觉收敛被藏入辅助配置；区域标题、控件位置及当前值能否帮助首次使用者判断在哪里操作，是否需要靠长说明才能找到入口。
- 主区、辅助区及详情是否重复同一内容或要求反复选择同一对象；辅助查看和配置是否能在约定上下文中完成。控件可点击、链路可完成只证明功能可用，不能代替上述体验比较。

- 主操作是否明显，次要和低频操作是否降级。
- 按钮文案是否描述结果，而不是只有模糊动词。
- 新建、编辑及补充流程中，同角色主次操作的位置、顺序与可达性是否可预期；差异是否有任务依据，不能仅因一个操作区固定、另一个自然滚动就判缺陷。
- 纯图标按钮是否有 tooltip 或足够上下文。
- 搜索、筛选、重置、保存、取消、删除、导入、导出、排序、分页、列设置是否出现在用户预期位置。
- 表单是否有 label、必要 placeholder、校验、提交反馈和恢复路径。
- 弹窗和抽屉是否有清晰标题、关闭路径、主按钮、次按钮和提交中状态。
- 标签页、步骤、筛选、分页、排序、列设置的状态保留或重置是否可理解。
- 破坏性操作是否在必要时确认或提供恢复路径。
- hover、active、focus、selected、disabled、loading、success 状态是否可见。

## 7. 操作与控件必要性

围绕每个用户意图核对必要性、承载方式和反馈，不按控件数量判断好坏。

### 是否需要当前操作入口

- 控件服务哪个意图，频率和优先级是否值得出现在当前层级；不保留为了显得功能完整而存在的控件或作用不明的开关。
- 是否已有状态、文字、行、标签、筛选、tab 或其他入口安全清晰地承载同一意图；合并重复筛选和动作，第二路径只有明显提升可发现性或安全性时才保留。
- 每个区域保留一个主命令；低频设置或多选项操作按任务归入菜单、设置面板、抽屉或更多入口。

### 用什么承载及怎样反馈

- 保存、提交、删除、新建、导入、导出、重试、确认、取消、运行、停止等明确命令使用按钮；破坏性、不可逆、异步或权限敏感操作须结合契约判断，不为减少按钮改成含糊入口。
- 低风险、高频、行内局部操作优先用行内动作；导航、筛选、钻取或展开目标明确时，优先用行、标题、标签、状态或数量承载，不在旁边机械增加“搜索 / 查看 / 详情 / 选择 / 打开 / 管理”按钮。
- 列表选对象可由列表项承载；表格存在多个可进入详情的安全文本时，选名称、标题或编号等稳定目标，避免重复入口挤占主路径。
- 可点击内容在操作前有可识别线索，文案能预测结果，操作中及完成后有可见反馈；触摸不能只靠 hover、cursor 或 tooltip。背景和边框按角色与上下文判断，不要求全部有或全部无边框，也不让纯文本误显为可点。
- 不可用操作按项目契约隐藏，或置灰并说明原因；核对是否仍需承载必要信息，具体见下方编辑态与阅读态检查。

### 定级

- 冗余控件让主路径不清楚或产生误导：`P1`。
- 冗余按钮造成页面拥挤但不阻断使用：`P2`。
- 更直接的文字/状态交互能提升精致度：`P3`。

### 编辑态与阅读态对照

- 阅读时是否仍显示仅服务编辑的分类选择器、填写提示或必填标记，且只是重复分组标题、标签或正文？这些项应隐藏，不能只置灰、换成重复标签或保留空工具区。
- 被隐藏控件是否承载唯一的业务值、单位、状态或条件关系？核对静态展示是否完整保留这些信息，以及展开、复制、跳转等必要阅读入口是否仍可用。
- 是否混淆阅读态与保存中、加载中、前置条件不满足或权限受限？按当前任务与项目契约判断保留、隐藏及不可用原因，不能机械删除所有禁用控件，也不能要求阅读态保留全部编辑控件。
- 实际切换编辑与阅读模式后，检查必要内容、值和分组状态按既有契约保留；隐藏项不占布局与键盘焦点路径，切回编辑后分类与填写入口恢复。静态检查未覆盖切换行为时明确证据缺口。

## 8. 状态完整性

检查：

- 默认态
- 编辑态与阅读态（存在模式差异时）
- 加载态
- 空数据态
- 筛选无结果态
- 错误态
- 禁用态
- 选中态
- hover 和 focus 态
- 提交中或运行中态
- 成功反馈
- 长文本和极端值
- 无权限、不可用或权限受限状态
- 慢网络或请求失败状态

状态规则：

- 空状态说明为什么为空，以及用户下一步能做什么。
- 筛选无结果状态提示清空或调整筛选。
- 错误说明发生了什么、是否能重试、用户如何恢复。
- 加载占位尽量保持布局尺寸。
- 禁用原因不明显时，应提供原因。

## 9. 动画与反馈

检查：

- 动画是否说明状态变化，而不是装饰页面。
- 动画时长是否适合高频工作。
- 加载、骨架、过渡、展开收起、弹窗、抽屉、菜单是否不闪烁。
- hover、加载、切换 tab、筛选、刷新时是否没有布局跳动。
- 高频工作界面是否避免吸引注意力的动效。
- 反馈是否不会阻塞无关操作，除非动作确实必须阻塞。

## 10. 说明与指引

检查：

- 必要说明是否靠近相关控件。
- 复杂控件是否有简短 helper text、tooltip、hint 或示例。
- 首次使用概念是否有帮助入口，但不把文档铺满页面。
- 指标、比较结果与解释入口是否对应同一范围或局部选择；位置是否让用户误以为说明属于另一项读数。按阅读和对照需要判断就地说明、展开或弹层，不把单项折叠本身定为缺陷。
- 空状态、错误、破坏性操作、不可逆操作、权限受限状态是否解释清楚。
- 不用长文案弥补命名、布局或交互设计的问题。
- 按钮是否夹带挤压主操作的解释；就近帮助、确认和结果反馈是否各承接适当信息。影响决定的后果是否在执行前可见，不能只在成功后告知；简单操作是否被无必要的二次确认打断。
- 避免用可见文字解释显而易见的 UI 行为。
- 提示是否讲清当前结果与下一步，而不是堆叠浏览器存储、安全上下文等实现术语；备份、草稿与正式提交的结果是否区分清楚，避免把局部失败说成整次操作失败。
- 提示位置及视觉强度是否匹配影响范围、严重程度和恢复需要；字段错误应能定位并访问对应字段，页面次要信息不应反复打断填报。详情折叠后，关键结果与恢复入口是否仍可发现，不强制所有提示放标题或全部自动消失。
- 相同任务的搜索提示、字段帮助和动作名称是否跨页面一致；不同结果不能为了文案统一而混淆。

## 11. 响应式与视口

按共用验证方法确定目标视口。在支持范围内检查文字可读、操作目标、导航、表格、筛选、弹层、横向溢出和文字重叠；不把未声明的移动支持当作缺陷。

## 12. 任务状态与连续性

桌面与移动任务界面均适用，按当前改动涉及的列表、输入、图表和导航选择检查项。

### 密度、数字与语义色

- 先看项目最窄支持视口；关联短字段是否合理并排，工具入口是否错误套用主按钮体量。用多条件与长值检查筛选区，不只看一个默认条件；已选条件应可发现、可直接编辑，不能被工具按钮挤成窄列或重复 tab/搜索状态。
- 扣除固定区域后，正文是否仍能有效阅读与操作；紧凑化优先减少重复标题、统计、说明和无效留白，不能以压缩命中区替代。报表卡片的数值、条数和入口是否有清楚层级，是否被拆成过多独立行。
- 任务分组是否可识别，标记是否被误画成按钮；必要的层级功能应保留，不能用删除代替改善外观。候选帮助应就地出现，不为每个字段重复同一句说明。
- 数据范围条件与分组、排序等展示工具是否能从名称、分组和当前值区分；只有一个有效选项时，选择入口是否仍有实际作用。检查无数据、不可计算与真实零值是否可辨，不能只为形式完整常驻大量占位指标。
- 数值展示按项目精度约定检查整数、非整数、零值和长值，并比较填报、编辑、列表与报表；整数是否出现多余全零小数，非整数是否被误截断，输入中的小数点是否被提前改写。金额、数量、条数与百分比按各自语义判断，不自行规定统一精度或颜色。
- 比较报表摘要、卡片、排行与固定读数的实际颜色及深浅主题；语义色 class 存在但被局部选择器覆盖仍是缺陷。结合邻近标签、图例和符号判断含义是否清楚，不能以细小符号已着色代替整体可辨识，也不统一要求全部数字着色。名称、操作入口与数值的视觉角色应清楚，必要时保留非颜色线索。

### 滚动与内容可达

- 按项目约定识别页头、筛选、正文、操作栏、导航和弹层的滚动归属；在内容顶部、中部、底部检查固定区域和滚动条边界，不因某个页面有固定页头就要求所有页面固定。
- 滚到末端，检查卡片结束、固定动作、导航和安全区之间有无重复占位、缝隙或遮挡；短内容也检查。核对透明区点击和输入期间的动作可达性，区分操作行背景与按钮自身背景。
- 同角色滚动位置提示的显示、停止后消退和再次滚动恢复是否一致，是否截获手势或越过滚动边界；页面隐藏或关闭后不应有残留，具体时序取自项目规范。
- 长管理列表、选择列表和日常列表检查最后一项是否可达，区分容器裁切与服务端只返回一批。分页、加载更多或搜索引导须反映真实后续状态；已有明确分页时，不重复铺操作说明。末尾反馈与同类列表对齐，分页检查当前状态、禁用态、操作命中区与加载反馈，不能只评价默认外观。

### 顺序调整（涉及时）

- 排序入口、允许范围和结果是否可发现，目标用户是否有可用的非拖动路径；不把拖动或逐行移动按钮作为默认标准。分组、分页与筛选后的局部列表，实际可调整范围是否与界面线索一致。
- 采用拖动时检查有效落点、边界滚动、拖出与取消，结束后是否误开详情；支持的键盘或其他替代路径是否表达同一移动结果。不能用动画顺畅替代操作完成的证据。
- 保存中是否避免重复或冲突操作，取消与失败是否恢复或明确保留待保存顺序；成功后刷新或重新进入是否呈现已保存结果。持久化算法与权限归业务/代码审核，本节检查用户可观察的结果。

### 输入、弹层与反馈

- 按支持的输入方式切换焦点，区分焦点、展开、选中与按下反馈；原生选择点选或取消后检查有效焦点，不能靠强制失焦消除高亮。选中状态不应随失焦丢失，键盘焦点也不应被选中样式掩盖。
- 复合控件从入口交接到搜索输入时是否出现两层重复强调，内部动作是否仍有必要的键盘焦点；弹层初始焦点是否适合当前任务，关闭后是否回到有效入口或错误抢回新任务的焦点。不规定统一色相或所有弹层必须聚焦同一按钮。
- 覆盖候选浏览、主动搜索、选择、取消、外部点按、字段切换、页面离开与返回。核对临时搜索与已选值、草稿是否正确，关闭后是否抢回焦点或自动重开。
- 按约定逐一检查关闭按钮、外部点按、返回和键盘取消：是否只退出目标层、是否绕过未保存或提交中保护；从正文拖出、遮罩滑动和关闭子层的同一次点击是否误关父层或触发底层操作。
- 从父任务进入辅助子层再取消，是否回到有效父层并保留草稿、位置与焦点；子表单的丢弃确认是否误清父草稿。成功后若原对象已失效，是否退出过时详情；失败是否留有重试或取消路径。辅助命令使用的已保存值与未保存输入是否被混淆，只记录可观察影响，领域规则交业务审核。
- 短抽屉、低可见高度、长候选和错误态下，搜索、完整候选行与动作是否可达，内部能否滚动；清除/重置是否需要滚完整个长列表，取消搜索是否误清已选值。展开方向与空间恢复按项目约定判断，不统一要求向下；可见视口内仍可能受所属容器或固定区裁切，不能依赖不存在的滚动范围让位。
- 键盘往返、异步候选到达及过渡结束后，浮层是否仍跟随有效锚点、保持内容可达；布局与滚动修正是否反复导致缩小、换向或跳动。初次打开时位置正确不能证明后续状态稳定。
- 在成功消息出现、消失及辅助提示切换前后，比较页头、工具栏、正文起点和主按钮位置，检查遮挡与整页跳动。成功反馈是否按约定自动结束，错误和恢复入口是否仍有足够阅读与操作时间；不强制所有消息使用同一位置或超时。
- 有弹层时实际触发成功与失败，检查消息及恢复动作是否被遮罩、顶层或焦点限制挡住；子层关闭后反馈是否仍能理解和操作，关闭消息不应误关任务层。
- 指针与焦点离开、触摸结束、数据更新和页面隐藏后，瞬态提示是否按约定关闭；持久选择态与应消失的提示分开判断。
- 在项目支持的主题下，点击/按下/聚焦/选中时检查列表与卡片的圆角、边框及高亮，是否出现非预期底色漏出、焦点裁切或残留遮罩；按设计契约区分有意的深色边框与渲染缺陷，不能用正常态截图代替。

### 导航与恢复

- 辅助管理关闭是否返回原任务并保留内容；切页面是否保留约定状态，同时关闭隐藏页浮层并暂停活动资源。覆盖共享组件的受影响消费者，包括编辑弹层和隐藏后返回。
- 分别检查首次进入、滚到中部后切页返回、下钻返回以及之后再次滚动再返回；按约定核对位置，覆盖数据延迟或刷新接替请求。只测一次返回不能发现旧 URL 位置反复覆盖最新滚动的问题。
- 来源标记、返回入口与查询条件是否同步遵循各自生命周期；按约定结束来源或重置条件后，再从常规导航进入，检查过期返回入口是否复活、返回是否形成循环。不把清除筛选与结束来源默认视为同一动作。
- 布局断点、触摸能力、平台与浏览器 API 可用性分别核对；窄视口不能证明手机环境。若问题与 HTTP 或可选客户端能力有关，检查实际访问方式与能力失败反馈，不能把测试环境的可用性当作所有入口均可用。

## 13. 触摸与原生输入

仅在声明的目标平台和受影响输入能力涉及时执行；混合输入设备保留指针与键盘路径。具体策略来自项目要求，证据有效性按共用方法判定。

### 触摸意图

- 快速滑动、到顶/到底继续拖动、反向拖动时，区分系统惯性、局部边界缓冲、滚动传递与整页移动；修复越界后是否把正常滚动变得生硬，是否带动原本固定的区域。
- 分别实测短按、长按、拖动取消和滑动结束，检查滚动是否误开详情或菜单；低频操作是否有可发现的替代入口。是否需要左滑取自用户任务与项目约定，不把手机端默认等同于需要左滑。
- 可点击按钮、卡片长按是否出现不合任务的原生选词或复制菜单；调整后输入、文本域和需复制正文是否仍可操作。整块蓝框先辨别选区、点击高亮还是焦点，修复后检查键盘操作的可见焦点，不能以全局禁选或去 outline 判通过。
- 触摸用户是否能读取完整数值，是否依赖 hover，手指是否遮住读数；按任务评价固定读数、图上标注或主动选择，不统一禁止所有 tooltip。
- 从图表区域开始滑动页面，是否误选数据或触发下钻；手势、明确命令与读数是否各自可预期。

### 原生输入与软键盘

- 在目标平台比较普通输入、原生日期/时间、选择控件与帮助文本的实际文字位置；分别检查横向起点、基线和垂直中心，按任务保留合理的角色差异。
- 键盘或视口适配改动检查展开、收起和再次聚焦的完整往返，并按页面实际结构覆盖字段切换、靠下字段及关联区域展开。检查页头位移、内容遮挡、底部空白与滚动恢复；旧的收起修复不能覆盖新焦点，不能以一次键盘展开正常判通过。
- 按平台检查聚焦缩放、连续点按、主动缩放、原生日期/选择器与实际键盘占屏；不通过禁用全部缩放掩盖输入问题。
- 涉及系统键盘或原生控件限制时，区分网页可控行为、系统界面与实现缺陷；按目标平台版本查官方能力或实测依据后再下结论。自绘输入或原生容器属于有取舍的方案，不能作为无感修补自动替换现有交互。

## 14. 问题质量

每个问题必须包含：

- 优先级。
- 页面或组件位置。
- 可观察现象。
- 为什么重要。
- 具体修复方向。

不要输出：

- 没有证据的个人审美。
- 纯业务逻辑批评。
- 没有具体原因的大重做建议。
- 能通过移除、合并、折叠、让现有文字或状态直接交互解决的问题，却建议新增更多 UI。
