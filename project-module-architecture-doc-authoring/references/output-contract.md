# 模块与技术专题文档输出契约

本文维护基于当前实现的技术说明内容；主题识别、路径和证据状态见 [主题发现与证据规则](module-discovery.md)。生成前读取 [文档结构规范](~/ai-agent-config/config/force/document-output.md) 与 [共用声明骨架](~/ai-agent-config/config/force/document-boundaries.md#共用声明骨架)。

## 参考结构与产物边界

采用**参考结构**，标题准确表达技术主题；功能模块可用“{模块名称}模块架构”，系统架构、部署架构或技术解析使用对应名称。没有固定的章数或统一标题要求，项目/用户明确的固定契约优先。

```markdown
# {技术主题}

## 用途与范围

本文面向开发者，解释{主题}在{系统/代码范围}中的当前实现，维护{本主题的组成、机制、依赖和技术约束}。
{逐环节业务状态、权限与字段规则/环境操作清单/接手评估等相关内容}由{已存在的权威正文或当前归属}维护；本文保留理解技术所需的摘要和引用。
依据范围：{代码版本、事实截止点和验证限制}。

## 技术全景与边界
## 核心机制
### {机制或代表性技术链路}
## 接入、扩展与变更影响
## 验证入口与已知限制
```

组织遵循 [面向读者的组织与审阅](~/ai-agent-config/config/force/document-output.md#面向读者的组织与审阅)，围绕技术机制或代表性运行链路，将问题、实现依据、行为、约束和复核方式就近说明，不为凑章节填充。共用机制集中维护，局部章节引用并补差异。未知不能当作不适用；没有持久化、权限或配置等对象时按事实说明，必要时简述依据，不创建空清单。

## 所有主题的最低内容

| 主题 | 必须回答的问题 |
| --- | --- |
| 定位与边界 | 解释什么问题、负责/排除什么、所属系统和代码范围、调用者、核心输入输出及当前结论 |
| 组成与关系 | 各单元职责、主要入口、调用或数据方向、所有权；区分逻辑模块、公共包、进程、容器及一次性任务 |
| 工作机制 | 从触发到结果解释关键处理、机制约束及证据；按实际覆盖算法、事务、状态、缓存、并发、消息、扩展点或错误处理 |
| 使用与接入 | 上游如何消费、必要条件、调用或配置方法、成功判据及失败反馈；无用户界面时写代码/任务/API 接入 |
| 依赖与变更影响 | 构建、运行、数据、配置及部署依赖按实际区分；输入输出、必需/可选、失败影响、兼容要求与责任边界 |
| 验证与限制 | 相关测试/CI/手工复核入口、运行条件与证据状态；风险、已知限制、待确认事项及影响和验证方法 |

每个关键结论关联可复查的文件与符号，不穷举源码。首次出现的术语解释在本系统中的作用。技术选择的动机只有找到依据才写；重点解释实际机制带来的行为与约束。

至少走通一条代表性技术链路：入口 → 处理单元 → 数据/状态或配置效果 → 输出 → 失败边界。它用于解释机制，不要求按每个业务动作重复同样分析。图表在复杂关系、异步或分支时使用；简单链路用文字或表格，数量不固定。

## 按事实展开的技术内容

### 数据、状态与权限

- 说明表、文件、缓存键、消息或数据结构的职责、关联、所有权和关键技术约束，覆盖理解主题所需的字段；不输出全部字段字典。
- 技术状态机属于本主题时说明状态迁移、触发/终止、幂等、重试和补偿，例如任务调度状态。业务专属状态机已有闭环文档时只保留必要摘要与引用。
- 鉴权、行级过滤、多租户、资源归属、审计和敏感字段机制按实现解释，明确前后端校验边界；不从按钮显隐或框架默认行为推断后端授权。
- 流程专属的“谁能在何状态执行何操作、字段怎样赋值及被哪个环节消费”归业务闭环正文。没有闭环文档时保留解释本主题所需的局部实例，不因此生成整套闭环报告。

### 配置与扩展机制

- 追踪配置从示例文件、启动脚本、环境变量、配置文件或密钥载体到消费代码的链路，解释实际覆盖优先级。
- 关键项说明用途、类型/单位、必填性、默认值、适用环境、校验位置、生效阶段与重建/重启要求；区分构建期/运行期、浏览器可见值/服务端秘密。
- 配置机制是主题关键时，用非敏感示例说明设置、注入、读取、行为与确认生效；说明缺失、非法值、冲突的结果。
- 存在新增类型、插件、适配器、任务或组件扩展时，说明扩展入口、注册/发现机制、生命周期、约束与相关验证位置。

### 系统与部署架构

系统全景、部署架构均属于本技能；按请求聚焦相应主题，不因写部署架构自动生成系统全景或运维手册。

- **系统组成**：能力、代码包与运行单元的映射；客户端、代理/网关、服务、任务、数据、中间件和外部系统的职责、调用与故障边界。共享机制引用所属专题，不逐个模块复制实现全文。
- **制品与装配**：源码版本、构建顺序、产物/镜像标识、内部制品依赖、配置注入及初始化/迁移与启动的先后关系。解释谁构建、谁启动、谁存数据，不把构建工具当常驻服务。
- **网络、权限与存储**：入口和请求路径、端口暴露、网络及身份边界、持久化目录/卷、临时产物、密钥/证书来源和外部资源所有权。
- **生命周期机制**：首次初始化、启动、升级、回滚、备份恢复在仓库中如何支持；说明触发与顺序、版本/数据兼容性、幂等或不可逆约束、健康检查和失败恢复机制的代码/脚本入口。没有实现的能力不能补写成现有方案。
- **构建发布链路**：存在 CI/CD 时连接触发、检查、构建、标识、分发、配置、发布、健康检查和回退，区分自动化与人工交接；CI 通过不代表部署成功。
- **环境区别**：区分源码默认值、开发配置、部署定义和已核实的环境事实。具体环境只作为解释方案的必要例证，标明来源、版本、差异和验证限制，不把环境例外升级为通用要求。

这里解释机制、材料和技术约束，必要命令可用于接入或复核；逐台服务器的账号/目录清单、日常启停命令册、升级执行单、值班排障和恢复操作程序由已有运维手册维护。没有手册时指出入口或缺口，不自动代写。

### 性能与兼容

存在并发、队列、缓存、长任务、大数据量或资源成本时，解释容量边界、背压/超时、资源释放及失败影响；存在历史数据、协议或平台差异时说明兼容机制和消费者差异。只记录证据支持的限制，不编造容量指标。

## 验证、风险与维护

验证入口列出实际相关的单元、集成、契约、E2E、扫描、CI 或手工方法及覆盖目标，不要求每种都存在。命令与运行结果使用发现规则中的状态；无测试时说明检查范围和风险，不编造命令或覆盖结论。

局部风险紧随机制，跨主题风险集中说明，可使用：

| 类型/影响等级 | 事项 | 证据状态与位置 | 影响 | 建议或验证方式 |
| --- | --- | --- | --- | --- |

类型按实际区分实现、数据/权限、依赖、限制与证据缺口；证据区分已确认、推断、缺失，不用推断冒充故障事实。未决索引只链接正文，不复制风险解释。

更新保留有效技术事实，局部维护不重排全文；整体重构修复受影响锚点。机制变化更新所属正文及消费方摘要；流程规则变化更新闭环正文；入口变化同步 README/索引。接手报告的历史结论不自动改写，重新评估时才更新其版本范围。

按技能入口执行结构校验与事实回查，逐篇检查技术问题是否解释完整、代表性链路是否可复核、是否与闭环/运维/接手文档重复维护。同一专题缺少事实不能由总索引替代，格式通过也不代表运行验证通过。
