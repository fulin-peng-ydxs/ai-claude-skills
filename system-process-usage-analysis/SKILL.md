# 进程资源分析

## 职责与边界

本文维护进程采样、归类与只读分析流程；报告只承载本次资源快照，停止或重启进程按下述授权与身份核对要求执行。

### 目标

基于当前时刻的只读进程快照，定位 CPU、内存或 IO 压力的主要来源，并把同一应用的宿主进程和子进程合并分析，避免只罗列碎片化进程名。

## 输入与前置条件

输入为当前系统及用户指定的应用或进程范围；识别可获取的 CPU、内存、IO、线程和父子关系，不将无法测量的指标填零。

## 执行流程

### 工作流

1. 采集系统总体资源压力、进程总数以及用户进程和系统进程分布。
2. 分别识别 CPU、内存、IO、线程数和子进程数量的高占用项；当前系统无法可靠提供某项指标时明确说明。
3. 按浏览器、IDE、Java、Node、Docker、数据库、聊天、同步工具和系统服务等实际类型聚合。
4. 结合资源维度、进程树、启动时间和持续性判断 1 至 3 个主要嫌疑项；单次采样不足以证明长期异常时只给观察结论。
5. 输出结构化报告和从低风险到高风险的处理建议。

## 核心约束

### 证据与操作边界

- 结论只代表本次采样；资源波动明显时补充采样或明确瞬时性。
- 默认只查看、统计和分析，不结束、重启或调整进程优先级。
- 用户要求结束进程时，先重新核对 PID、进程命令、所属用户和父子关系，说明影响并取得明确同意。
- 不使用宽泛的 `pkill` 或模糊名称匹配处理进程，不主动终止系统关键进程。
- 操作后重新采样，报告目标是否结束、资源变化和仍在运行的关联进程。

## 产出边界与交付

默认在对话中交付，用户要求保存时按指定路径或全局规则落盘；诊断不自动授权结束或重启进程。

完整报告生成前读取 [固定产物模板](references/output-template.md)，由其唯一维护目录、字段及内容验收；只要求摘要或局部分析时遵循明确范围，保存和局部更新保留基线。

## 验证与完成标准

核对采样范围、时点、单位和聚合关系，区分瞬时高占用与持续异常。获准操作后重新采样并说明实际资源变化，未执行的处理只列为建议。
