# 进程资源分析

## 职责与边界

本文维护进程采样、归类与只读分析流程；报告只承载本次资源快照，停止或重启进程按下述授权与身份核对要求执行。

### 目标

基于当前时刻的只读进程快照，定位 CPU、内存或 IO 压力的主要来源，并把同一应用的宿主进程和子进程合并分析，避免只罗列碎片化进程名。

## 输入与前置条件

输入为当前系统及用户指定的应用或进程范围；识别可获取的 CPU、内存、IO、线程和父子关系，不将无法测量的指标填零。

## 执行流程

### 工作流

1. 采集系统总体资源压力、进程总数以及用户进程和系统进程分布。
2. 分别识别 CPU、内存、IO、线程数和子进程数量的高占用项；当前系统无法可靠提供某项指标时明确说明。
3. 按浏览器、IDE、Java、Node、Docker、数据库、聊天、同步工具和系统服务等实际类型聚合。
4. 结合资源维度、进程树、启动时间和持续性判断 1 至 3 个主要嫌疑项；单次采样不足以证明长期异常时只给观察结论。
5. 输出结构化报告和从低风险到高风险的处理建议。

## 核心约束

### 证据与操作边界

- 结论只代表本次采样；资源波动明显时补充采样或明确瞬时性。
- 默认只查看、统计和分析，不结束、重启或调整进程优先级。
- 用户要求结束进程时，先重新核对 PID、进程命令、所属用户和父子关系，说明影响并取得明确同意。
- 不使用宽泛的 `pkill` 或模糊名称匹配处理进程，不主动终止系统关键进程。
- 操作后重新采样，报告目标是否结束、资源变化和仍在运行的关联进程。

## 产出边界与交付

首次生成或获准补全文档时落实下述产物边界；仅保存、逐字保存或局部更新沿用有效基线，不为补边界扩写或重排，范围外缺口在交付中说明。

默认在对话中交付，用户要求保存时按指定路径或全局规则落盘；诊断不自动授权结束或重启进程。

### 产出文档边界

生成报告前读取 [共用声明骨架](~/ai-agent-config/config/force/document-boundaries.md#共用声明骨架)。报告说明本次采样范围与时点的资源压力、嫌疑进程和处理建议；不作为长期监控结论或服务运维规范，实际操作结果与诊断建议分别表述。边界并入报告概览。

### 报告内容

按 [文档结构与输出规范](~/ai-agent-config/config/force/document-output.md) 使用**参考结构**，在用户要求的范围内组织以下内容。采样范围与时点、资源压力、高占用进程及分类、嫌疑依据和处理顺序必须明确；无法测量的指标保留缺口说明，不编造嫌疑项或把瞬时快照写成持续性结论。

组织遵循 [面向读者的组织与审阅](~/ai-agent-config/config/force/document-output.md#面向读者的组织与审阅)，以应用及其进程组为分析单元：

- 概览：说明本文用于本次资源压力排查，记录嫌疑进程、证据与处理建议，长期监控与运维规则沿用已有入口或说明当前归属；列出采样范围与时点、进程数量、CPU/内存/IO 压力及程序分类统计，说明聚合口径和测量限制。
- 高占用与嫌疑明细：保留各资源维度的 Top 进程导航；同一应用的 PID/父子关系、启动时间、资源占用、持续性证据、是否主要嫌疑及原因放在同一条目，避免重复列成几份结论。
- 处理与复核：在嫌疑项旁说明继续观察、关闭应用、重启服务或进一步诊断的建议、影响和再次采样的判断方法；末尾仅汇总从低风险到高风险的处理顺序与共用盲区，不重复具体建议。

Top 排名与进程组聚合值分别标注，不能重复累计宿主和子进程指标。操作授权、目标身份复核及实际操作后复采要求仍按核心约束执行，诊断建议不代表已处理。

## 验证与完成标准

核对采样范围、时点、单位和聚合关系，区分瞬时高占用与持续异常。获准操作后重新采样并说明实际资源变化，未执行的处理只列为建议。
