# 技能编写规范

## 职责与边界

本技能用于创建或重构用户自有技能及统一技能名称。本文维护编写流程、正文组织与裁剪规则，[命名规范](references/skill-naming.md) 维护标识、中文名称及重命名契约，[默认骨架](references/skill-template.md) 维护结构与填写提示；全局文档规范维护通用原则，具体业务规则、工具选择及产物模板由目标技能维护。

- 创建或获准整体重构技能时使用本规范；局部修改保留有效原结构，不借机扩写或重排。
- 复用 [共享 skill-creator](~/.codex/skills/.system/skill-creator/SKILL.md) 的文件契约、初始化与基础校验能力；本技能只补充用户的结构约定，不复制其教程或修改系统技能。
- 用户明确请求从参考产物创建可复用模板技能时，由 `template-creator` 承接专用流程；本技能不替代它。
- 不自动修改全局路由、同步到其他工具、提交 Git 或批量迁移已有技能。技能可被自动选择，不代表已配置全局默认入口。

## 输入与前置条件

从用户请求、目标技能及相邻技能确定使用场景、负责和排除的事项、所需输入、交付物及目标目录。只追问影响职责或正确性且无法由现有事实确定的信息。

先读取适用协作入口与目标目录规则，检索同类技能及引用关系，并对照相关输出契约或模板，判断应新增、扩展既有技能还是保留分工。明确核心规则、事实、流程和验证能力由谁维护、其他技能如何消费；不要仅因名称不同而创建同职责入口，也不能只看技能描述就认定产物没有重叠。

遵守 [文档结构与输出规范](~/ai-agent-config/config/force/document-output.md) 和 [文档边界规范](~/ai-agent-config/config/force/document-boundaries.md)。通用规则保留在原权威位置，目标技能只引用适用入口并补充专项要求。

## 执行流程

1. **确定范围与基线**：识别新建、整体重构或局部修改；以修改前的实际文件（含已有未提交改动）为基线，检查职责、调用关系和稳定契约，保留有效授权与用户选择。重构前按下述语义保留审查提取核心契约；局部修改只提取受影响契约及关联约束，新建技能以用户要求和适用规范为依据。
2. **设计入口**：创建或重命名时先读取 [命名规范](references/skill-naming.md)，先选统一一级领域，再确定细分对象与任务能力，核对同职责入口和标识冲突。用简洁的 `description` 表达能力和触发场景，仅为容易误触发的相邻任务写排除条件。正文明确与相关技能的分工。
3. **组织内容**：新建或整体重构时读取 [默认骨架](references/skill-template.md)，以六类主题组织正文；按实际规模合并或展开，保留适用的关键判断、异常处理和完成条件。
4. **落地资源**：需要初始化时复用 `skill-creator` 的 `scripts/init_skill.py`。按下述“正文与独立资源的选择”确定承载位置及整合范围，引用处标明读取时机；只有重复执行或确定性收益明确时才新增脚本。简单技能不必拆分参考文件。
5. **核对与验证**：对照基线完成语义保留审查、关键场景推演和适用的格式及运行验证；发现问题先修复再复核受影响部分。交付实际路径、变更依据、执行证据及未验证项，不以格式通过代替内容保留结论。

## 核心约束

- 调用标识、中文名称和 UI 名称遵循 [命名规范](references/skill-naming.md)；已有标识保持稳定，不因标题中文化或局部修改自动改名。获准重命名时同步处理引用与对应副本，不保留两个可发现的同职责入口。
- 正文采用**默认骨架**，不是固定标题契约；职责与边界、执行方式、输出和完成条件必须可辨识。输入与专项约束有实际内容时保留，可并入相关章节，不为凑齐标题编造限制或保留空章。
- `SKILL.md` 本身适用全局文档边界规范。在“职责与边界”中分别交代技能负责哪些工作，以及本文件维护哪些规则、相关规则由哪些入口维护；复用该章节，不另加同义的“文档边界”章节。
- “产出边界与交付”说明交付物包含与排除的内容、返回方式、落盘条件及保存位置，不承担技能文件之间的规则归属说明。简单技能可合并边界说明，不重复描述同一限制，不为声明归属而新建文档。
- 技能生成文档时，读取 [共用声明骨架与接入要求](~/ai-agent-config/config/force/document-boundaries.md#共用声明骨架)，在产物模板、输出契约或内联结构的实际生成位置承接该类文档的具体职责；不能只在技能中声明或在模板外提醒遵守规范。首次生成或获准补全时落实；仅保存、逐字保存或局部更新保留授权基线，范围外缺口在交付中报告。
- 未知、缺少权限或尚未验证不等于不适用；记录缺口及影响，不用模板补造事实。
- 优先沿用六类主题的阅读顺序；复杂技能可增加专项章节或按模式分流，简单技能可合并。调整结构不能删掉业务必需内容、条件触发和机器固定字段。
- 技能正文结构与生成的产物结构分开维护。产物模板声明参考结构、默认骨架或固定契约，并写清最低内容、适用条件和必要固定项；承载位置按下述选择规则确定，避免两套章节层级混杂。
- 面向读者的文档在输出契约、模板或内联输出位置接入 [面向读者的组织与审阅](~/ai-agent-config/config/force/document-output.md#面向读者的组织与审阅)，说明本类文档的主要组织对象；已有等价说明或明确生效的共用契约时复用，不在技能正文和多个资源中重复添加。保留保存、局部更新及固定格式边界，不要求提交消息、机器数据或仅执行操作的技能套用报告结构；生成提示不原样写入交付文档。
- 同一规则只有一个权威位置。目标技能仍须提供自足执行所需的业务上下文，不能退化为链接目录；不得复制全局规范或加入历史流水、空泛自评和无用途示例。
- 验证语义覆盖和实际行为，不将六个标题或固定步骤数写入强制检查器。机器契约和真正固定的输出字段按已有校验执行。

### 正文与独立资源的选择

按读取场景、维护职责与复用收益选择，不按字数或文件数量机械拆合；这是技能内部资源的组织规则，不要求生成的业务文档照搬同一文件结构。

| 承载位置 | 选择依据 |
| --- | --- |
| `SKILL.md` 正文 | 保留职责、模式选择、共用流程、关键授权与停止条件、输出及完成判断；短小且执行时总要一起理解的说明就地组织。专项细节移出后，正文仍能判断何时读取、执行什么及何时停止。 |
| 独立参考文件或产物模板 | 有独立读取场景、独立维护职责或明确共享收益，且拆出能减少无关加载或避免执行流程与完整模板混杂时使用；如某模式的详细流程、领域规则或完整产物模板。引用说明读取条件与用途，不能将关键门禁只藏在可选资源中。 |
| 已有权威入口 | 全局规则、相邻技能能力或既有共用契约已维护的内容，直接引用或调用；本技能仅补差异和执行所需上下文，不复制完整正文、模板或验证逻辑。 |

多份文件总是共同读取、共同修改并解释同一对象，且没有独立维护或复用收益时优先整合；拆分收益应大于跳转和同步成本。合并保留必要信息、读取条件与引用，不为减少文件数塞成难以定位的超长正文，也不为缩短正文把完整判断链拆散。正文保留必要摘要与触发条件，详细定义只维护一处。

## 产出边界与交付

在用户指定位置创建或更新目标技能；未指定时沿用 `skill-creator` 的用户技能目录约定。交付有效的 `SKILL.md` 及实际需要的参考资料、脚本或元数据，不附加无用途的 README、变更日志和空资源目录。

说明调用名称、职责及验证结果。仅完成文件创建时，不宣称已完成自动发现、全局默认路由或跨工具同步；这些操作按用户另行授权的范围执行。

## 验证与完成标准

- 运行 `skill-creator` 的 `scripts/quick_validate.py <目标技能目录>` 检查基础格式；它不能替代内容和行为验证。
- 创建或变更名称、标题、UI 元数据时，运行 `python3 scripts/validate_skill_names.py <目标技能目录或用户技能根目录>`；脚本路径以本技能目录为基准。名称是否准确表达主要职责及相邻边界仍须人工核对。修改命名检查器后运行 `python3 -m unittest discover -s tests -p 'test_*.py'`。
- 检查新增或变更的引用目标、资源入口和 UI 元数据一致性，清除未完成脚手架；有新增或修改脚本时执行适用验证。
- 对受影响资源逐份核对独立承载的理由，并沿代表性任务检查加载顺序：是否为同一判断反复跳转、重复读取或维护相同内容；缺乏拆分收益时整合，不能只以每份文件都有内容判定合理。
- 分别核对技能的工作范围、技能文件的规则归属和产物的交付范围，检查文档模板或内联结构的实际输出位置及共用骨架引用是否承接边界要求，以及是否误将相邻技能的产物纳入默认交付；按实际内容判断，不以存在同名章节代替检查。
- 用目标技能的实际请求推演正常使用场景、容易误触发的相邻场景，以及适用的缺失输入或异常场景。对照相邻技能的输出契约或代表性产物，检查是否重复生成完整正文、维护同一规则或验证能力、自动扩展交付物；必要摘要与操作上下文不算重复定义。核对选择、输入获取、处理、输出和停止条件是否完整；不把推演称为运行验证。
- 按下述流程核对核心内容保留及引用和消费方兼容性。格式通过但职责冲突、必要信息缺失或关键行为未验证时，如实说明限制。

### 重构的语义保留审查

1. **提取核心契约**：修改前读取范围内的技能正文、相关参考文件、脚本和元数据，提取触发与排除条件、输入前提、执行分支、授权与停止条件、输出和保存规则、异常处理、验证标准及资源依赖。保留每项的条件、规则强度、例外、固定字段和来源位置，不把旧文本中的冲突或过期内容自动视为正确要求。
2. **逐项对照去向**：重构后将原契约对应到新位置，区分原位保留、合并表达、迁移资源、有依据的修改或删除。合并不得丢掉条件和例外；迁移后既要能从入口到达，也要在适用分支明确何时读取。引用存在不等于规则仍会生效。
3. **审查变更依据**：删除或改变核心契约时说明用户要求、有效上位规则、已核实事实或重复定义的权威承载位置。不能仅以精简、套模板或原句消失作为正确性依据；没有依据的遗漏先恢复，实质歧义保留并明确待决影响。反向检查新增内容是否扩大触发范围、权限、交付物或验证负担。
4. **验证关键场景**：按正常使用、相邻误触发、缺失输入及适用异常推演前后行为，重点覆盖本次改变的分支；声明行为不变时核对结果一致，确有契约变更时核对差异符合依据。涉及保存、仅审查或授权操作时，检查不会误触发重新生成、修复或外部写入。有脚本或确定性机器契约变更时执行适用测试，不用标题、字数或原句匹配代替语义验证。
5. **判定与交付**：全部适用核心契约均有可定位的去向或有效变更依据，且发现的问题已修复并复核，才能说明语义保留检查通过。交付简述对照范围、实质变化、场景推演或实测结果及未验证项；未完成的检查不得报通过。

对照在任务执行中完成，不默认创建长期报告文件；需要临时基线或检查材料时遵循临时产物规则。一般重构不强制子代理，执行者自审不称为独立审查。此流程约束技能编写过程，不复制进每个业务技能作为其日常任务流程。
