# 工作空间、初始化与手册

本文定义布局、首次接入和事实文档；授权执行只走 [主流程](../SKILL.md)。Markdown 产物的格式、字段及通用规范入口统一由 [固定模板](output-templates.md) 维护；局部更新保留范围外正文和事实粒度。

## 初始化

1. **收集缺项**：项目目录、首批服务器/单位、各服务对应的源码路径、环境/用途、地址或 SSH 别名、端口、账号、直连/跳板、凭据引用、主机指纹可信来源及用户明确的连接限制。逐服务核实源码所在机器、仓库绝对路径及对应模块子目录，区分源码与部署目录；已有资料不重复询问，不索取明文密码或私钥。路径未知时请求补充并保留缺口，第三方服务无自有源码时注明不适用依据，按固定模板记入单位手册。无服务器信息须请求提供；用户只要本地骨架或明确暂无服务器时可先准备，状态为待接入。
2. **准备入口**：复用现有目录，在 AGENTS 固定运维根；默认 `agent-works/operations/`，下文称 `OPS_ROOT`。先建真实服务器和连接白名单条目，复制技能默认命令策略，填入精确目标与本次初始化请求的真实来源即可采用，不另行请求批准默认表；身份或指纹未知的目标保持待核验，不连接。复用 `ai-constraint-doc-authoring` 补缺失 AGENTS/CLAUDE：前者只维护约束/导航，后者薄引用它；纯运维资料不作为本地程序安装、构建或启动。Git 缺失时确定纳管根及初始化授权，不误建家目录/嵌套仓库；无持久留痕条件时暂停，紧急例外须明确授权和替代证据位置。
3. **接入当前宿主Hook**：首次服务器操作前，按[Hook初始化接入](host-integration.md#初始化接入步骤)完成当前宿主的配置落地、必要信任和实际通道验证，并记录状态。已验证且未变化的接入直接复用；未验证或不支持时继续本地准备，暂停首次服务器操作。
4. **首次盘点**：当前通道Hook接入通过、连接白名单核对及严格主机密钥验证通过后连接，按[主流程审批判定](../SKILL.md#审批判定)处理命令权限和停止分支；核验身份/环境，识别范围内系统、服务、容器/Stack、端口、管理定义、配置/数据/日志和依赖。先定位再读取，不全盘扫描；按范围登记停止服务和定时/一次性任务。权限不足或工具缺失记缺口，不当不存在。
5. **生成资料和规则**：按下表写清单和手册；按[场景默认行为与例外规范](command-policy.md)使用完整默认基线，按事实填目标和管理入口，不为每个项目重新裁出一套少量规则。未知能力不补造、不安装；调用前核实工具可用性。场景模式切换或超出默认基线的放宽提交差异并取得批准；已有项目不自动覆盖原策略。用户明确拒绝长期放行时，将相关场景设为默认询问并保持空allow，不另配ask表。
6. **续接任务**：接入及必要资料核实后继续原任务，复用同一记录和有效授权，最后统一汇报归档；独立初始化直接汇报。未连接只算本地准备，阻断后续操作的缺口未解决不称目标就绪。

新增目标只接入新增范围；既有项目补缺复用有效证据，不重扫其他主机。初始化不自动装软件、加固、改账号/网络或部署监控备份；这些须有变更需求和方案。

## 文件与归属

既有权威路径优先。只创建有实际内容和消费方的文件；未知标来源缺口，无对应服务不生成示例手册。

| 默认位置 | 必须提供什么 |
| --- | --- |
| `AGENTS.md`、`CLAUDE.md` | 约束入口、运维根及下列文件的用途/读取时机，不复制技能 |
| 当前宿主Hook配置 | 路径及合并规则见[Hook初始化接入](host-integration.md#初始化接入步骤)；只维护当前宿主指向共享适配器的注册，不复制命令权限 |
| `OPS_ROOT/servers.yaml` | 稳定 server_id、环境、主机名、地址/别名、端口、账号角色、用途、单位成员、连接引用、证据/核实时点；未知 null，不存秘密 |
| `OPS_ROOT/access-policy.md` | 连接白名单：精确服务器、地址/端口、账号/渠道、连接命令、安全凭据引用及可信主机指纹；范围/期限/撤销条件。命中直接连接，提权和远端命令独立判定 |
| `OPS_ROOT/command-policy.json` | 目标/账号、共同deny及场景默认行为和唯一例外表；格式/迁移见命令策略 |
| `OPS_ROOT/index.md` | 按固定模板的 index 块 |
| `OPS_ROOT/units/<unit-id>.md` | 按固定模板的 unit 块 |
| `OPS_ROOT/servers/<server-id>/rootfs/` | 合规原件镜像；脱敏件/摘要显式改名，见留痕 |
| `OPS_ROOT/records/<YYYYMMDDHHmm[-序号]>/record.md` | 人工审阅入口：目标、方案、批准范围、结果、待办及归档；不嵌执行流水 |
| 同目录 `execution.md` | 精确命令、实际结果、必要证据及需求/批准来源，通过方案和操作编号关联审阅记录；附件触发见留痕 |

server_id、unit-id 为唯一小写 kebab-case；前者不随 IP 改变，同名服务的不同环境/集群用不同单位 ID，跨主机集群用同一 unit-id 关联成员。

## 总览与手册

生成前读取 [固定模板](output-templates.md)，按实际产物使用 index、unit 或 access 块。主体字段及内容验收只在该处维护。沿服务器、服务、管理入口定位精确操作；监听和进程存在不能证明公网可达或业务健康。

需要解释装配、网络/存储或生命周期机制时，复用 `project-module-architecture-doc-authoring` 更新已有权威正文；无正文且本次确需解释时才新建 `OPS_ROOT/architecture.md`。提供已授权取得的材料与证据，未知不反推；普通盘点不强制另写架构文档。

## 更新与验收

只更新受影响清单、手册和总览摘要；局部探查不删除其他环境/未覆盖对象，历史记录原样保留。沿“服务器 → 服务 → 管理入口 → 命令 → 成功/失败处理”查用，回查服务与源码路径的对应关系及部署路径、版本、成员和端口证据；引用齐全不能代替手册可用。
