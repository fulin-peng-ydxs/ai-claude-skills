# 运维工作空间契约

本文维护前置检查、目录与长期文档职责及架构编写协作；操作流程见 [技能入口](../SKILL.md)，审批及记录格式见 [留痕契约](records.md)。生成文档时读取通用 [文档边界](~/ai-agent-config/config/force/document-boundaries.md) 和 [输出规范](~/ai-agent-config/config/force/document-output.md)。

## 初始化与前置检查

以用户指定工作空间或已核实的项目根为起点；在 AGENTS 固定运维根目录。已有目录复用，不并建另一套定义；无约定时使用 `agent-works/operations/`，下文记作 `OPS_ROOT`，不是 shell 环境变量要求。

1. 读取现有 AGENTS/CLAUDE 和适用上级规则，核实本地目录、Git 归属、已有策略与事实引用；确定缺失文件和受影响内容，保留有效基线。
2. 按下述调用约定使用 `ai-constraint-doc-authoring`：仅缺哪个补哪个，完整缺失时创建两份。AGENTS 维护约束，CLAUDE 引用 AGENTS，不复制规则。运维事实和权限由本流程核实，不交由通用文档技能猜测。
3. 按下表创建必要文件的可用结构，缺失事实标明来源缺口和受阻操作；规则未确认前白名单为空。纯本地文档准备可以继续；身份、连接方式、授权规则或恢复条件等必要信息不明时，停止依赖它的操作。
4. 连接获准后补齐任务相关事实，检查证据时效性；不要因本任务初始化而对整台服务器做全量扫描。
5. Git 仓库不存在时，先确定纳管根与初始化授权；不能误初始化家目录或嵌套仓库。无法留痕时报告，紧急继续须有明确例外授权及替代持久证据位置。

### 调用 AI 约束文档技能

初始化时将以下输入一并交给 `ai-constraint-doc-authoring`，由它按自身输出契约和通用门禁编写、校验入口；运维专属输入与复核要求由本文维护。

- **目标与交付范围**：明确工作空间、需要创建/更新的 AGENTS/CLAUDE、已有有效内容及固定运维根。纯运维初始化先交付本地约束、授权停止条件和事实导航；工作空间确有需维护的本地程序时，其命令仍按通用技能门禁处理。
- **事实与必要导航**：提供下表中的连接策略、服务器清单、统一命令策略、架构、单位手册索引、镜像及记录目录的真实位置、用途与证据。缺失文件先按本流程准备可用结构，未知主机事实登记缺口，不生成示例服务器或失效链接。
- **执行与验证边界**：服务器镜像和手册内的包清单不是本地待运行项目，不据此安装依赖、构建或启动。未经连接授权不 SSH；不为编写入口执行启停、部署、升级、恢复等远端变更。远端候选命令在手册中保留“未验证、须经授权核实”，不得写成已验证日常流程；获批操作后按实际证据更新状态。
- **返回与复核**：接收文件路径、文档结构校验及未验证范围，核对导航齐全、CLAUDE 保持薄入口、未知身份/授权确实阻断远端动作。入口创建成功只证明本地交付，不代表服务器命令或运行状态验收通过。

## 目录和权威文档

```text
<工作空间>/
├── AGENTS.md
├── CLAUDE.md
└── agent-works/operations/
    ├── access-policy.md
    ├── servers.yaml
    ├── command-policy.md
    ├── architecture.md              # 无既有权威架构正文且需新建时使用
    ├── index.md
    ├── units/<unit-id>.md
    ├── servers/<server-id>/rootfs/<远端绝对路径去掉开头斜杠>
    └── records/<YYYYMMDDHHmm[-序号]>/
        ├── record.md
        ├── approvals.json
        ├── commands.jsonl
        └── manifest.json
```

目录图是默认布局；以下内容是最低契约，不要求照抄章节。生成时用真实目录和事实替换说明，不生成示例主机。`server-id`、`unit-id` 使用唯一小写 kebab-case，服务器 ID 不随 IP 变化而变化；相同组件在不同环境/集群用不同单位 ID。

| 文档 | 生成位置必须承载的职责和最低内容 |
| --- | --- |
| AGENTS.md | 明确维护本工作空间 AI 运维约束；指定运维根、连接与命令策略入口、服务器清单、架构、单位手册索引和镜像/记录目录用途；明确实际操作读取本技能。项目事实在相应文档维护。 |
| CLAUDE.md | 说明仅是 Claude 入口，指向同一 AGENTS；其他 AI 由其项目入口指向 AGENTS，不能生成各自独立白名单。 |
| access-policy.md | 维护安全连接与人工授权机制。账号角色、渠道、SSH 别名/堡垒机/跳板、主机密钥可信来源及核验、凭据引用、最小权限、授权人/审批渠道、授权范围/有效期/重连条件、撤销方式；具体单次审批在 records 中。 |
| servers.yaml | 以注释说明维护服务器身份及连接引用，不保存秘密；每台记录 server_id、环境、主机名、地址/SSH 别名、端口、用途、单位成员关系、账号角色、连接策略引用及证据来源/核实时间。未知值用 null 并说明，不能把缺失记成已验证。 |
| command-policy.md | 维护本工作空间唯一有效分类；按照命令策略契约填写版本、范围、deny/ask/allow、未匹配行为及策略审批依据。全局参考不直接视为已批准的工作空间白名单。 |
| 架构正文（默认 architecture.md） | 已有同主题权威文档时直接更新或引用，不再建立另一份；确需新建时按下节协作生成。维护机制、拓扑及技术约束，明确代码/部署定义与实际环境证据的差异；操作步骤归单位手册。 |
| index.md | 按 [运维总览契约](operation-index.md) 维护服务器—单位—手册导航、端口与必要定位摘要及目录用途；不存在手册写明缺口，不伪造链接，架构和操作正文不在索引复制。 |
| units/<unit-id>.md | 按单位手册契约维护该单位的职责、配置、依赖和操作步骤；跨主机集群记明成员与命令执行角色，不能仅按服务名字覆盖同名实例。 |

## 部署架构协作

本技能负责运维授权、执行及环境取证，`project-module-architecture-doc-authoring` 负责部署组成、装配、网络/存储和生命周期机制的技术解释。协作方式如下：

- 先检查已有架构正文及主题范围；同一主题直接更新或引用，不因运维目录固定就另写一份 `architecture.md`。确有需单独维护的环境差异时，在已有正文的环境分区或明确归属的环境说明中记录差异，并引用通用机制。
- 需要生成或更新架构时，交给架构技能：主题、读者、目标文件、已有有效内容、代码版本/部署材料，以及本流程已授权采集的服务器/单位、网络、存储、配置和依赖证据，附来源、时点、验证状态及缺口。
- 缺少源码或部署材料时按实际证据限定主题；不能从运行快照反推未证实的构建、发布或恢复机制。需要新增远端证据时回到本技能取得授权和采集，架构编写本身不授予服务器操作权限。
- 接收架构正文及其结构/事实核查结果；核对代码默认、部署定义与实际环境差异分别标注，未知依赖没有补造。总览只维护必要摘要与真实链接，单位手册维护具体执行步骤。
- 仅更新服务器或手册索引时不调用架构技能生成整份文档；架构缺失就明确缺口，影响本任务正确性或恢复判断时按主流程暂停依赖操作。

## 连接规则

- 首次连接前明确目标、账号、认证来源及安全渠道。优先使用既有 SSH agent、密钥引用、短期凭据或堡垒机；不把私钥/口令写入技能、Git、命令行或对话。
- 主机密钥从可信渠道核验；首次未知或指纹变化时先人工核实，禁止通过关闭校验绕过问题。
- SSH 转发、跳板、提权、复用长连接均须在连接/执行授权范围内；禁止仅因目录属于 root 自动 sudo。文件上传、下载及远程 API 也受同一范围约束。
- 连接后先核验身份和环境；只读也可能暴露敏感配置或产生高负载，遵守命令策略和最小采样。
- 授权失效、撤销、身份不符或重连目标改变时暂停。换工具不能以“工具支持”替代授权；把审批记录交给后续 AI 时同时给出可信来源和对应方案版本。
