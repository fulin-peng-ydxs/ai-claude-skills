# 运维总览与服务器盘点

本文维护服务器盘点、单位与端口汇总、运维总览的输出及验证；连接、命令授权、人工结果审批和留痕复用 [技能主流程](../SKILL.md)，不另起任务或重复申请已覆盖的授权。单位操作步骤由 [单位手册契约](unit-manual.md) 维护，部署架构的编写协作见 [工作空间契约](workspace.md#部署架构协作)。

## 使用范围与证据

用户要求生成/更新运维总览、整理服务登记册、盘点指定服务器，或本次变更影响服务器—单位—手册关系时读取本文。已有证据足够时直接维护文档；只有必要证据缺失时才在授权范围内只读探查，不为总览验证启停、部署或恢复。

先确定工作空间、环境、server-id、unit-id、采样范围及权威文档位置。优先维护已有同范围总览，无约定时使用 `OPS_ROOT/index.md`；`OPS_ROOT` 由工作空间 AGENTS 指定，默认 `agent-works/operations/`。单机探查只更新对应条目，多主机总览按 server-id/环境分组，不能用单机结果覆盖其他主机。

## 盘点流程

1. **核对已有资料**：读取服务器清单、总览、目标单位手册及架构中有关事实。按手册的环境和成员服务器判定归属，不仅按文件名猜测；跨主机集群按同一个 unit-id 关联各成员。
2. **采集目标元信息**：核实主机名、操作系统、运行身份、探测时间与时区；存在容器平台时核实版本及集群角色。服务器身份和连接引用维护在 `servers.yaml`，总览只呈现定位所需摘要。
3. **识别运行单元**：结合系统服务、进程、监听端口、容器及编排定义，登记宿主机服务、容器、Stack、一次性任务和调度任务；构建工具不能登记为常驻服务。先定位管理入口再读取必要配置，不默认扫描全盘。
4. **核实归属与关系**：把运行单元关联到用途、调用方、单位和成员服务器，整理端口矩阵与维护入口。配置引用、编排或实际调用可证明依赖；共处一台机器不能证明依赖。外部依赖标明外部归属和证据，不登记成本机部署。
5. **更新唯一正文与总览**：服务器身份变化维护服务器清单，操作步骤变化维护单位手册，架构机制变化按工作空间契约协作架构技能；总览更新摘要、真实链接、证据时点及缺口，不复制整份正文。新建手册后才加入链接，缺失写明缺口。
6. **验证与交付**：按下文核对代表性定位路径，报告真实文件路径、目标范围、已核实的服务器/单位/手册数量、更新项及未验证内容。探查与文档修改均回到主流程保存证据、汇报、审批和 Git 留痕。

可按平台选择以下取证入口；它们是候选，不是白名单，完整命令、参数、身份和输出范围仍须通过工作空间命令策略：

| 对象 | 候选证据入口 |
| --- | --- |
| 主机及系统 | `hostname`、`uname`、系统发行信息文件；分别记录主机身份与系统版本的来源。 |
| 宿主机服务 | 服务管理器的状态和单元配置、限定范围的进程信息；查询字段和输出先评估敏感性。 |
| 容器及集群 | `docker version`、限定字段的 `docker info`、`docker ps`、`docker stack ls`、`docker service ls`，或目标平台的等效只读查询。 |
| 端口与网络 | `ss`/`netstat` 的监听信息，结合实际进程/容器及编排定义确认服务归属；不能默认所有机器都使用示例端口。 |
| 路径与依赖 | 已定位配置、启动定义、挂载和日志；优先按字段读取并脱敏，避免整份输出容器环境变量、进程参数或凭据。 |

工具缺失、权限不足或没有采到结果分别记录，不能据此断言服务不存在。进程存在不等于业务健康，无当前连接不等于长期无人调用；源码默认值、部署定义和实际观察分开标记。

## 总览输出（默认骨架）

生成前按通用 [文档边界](~/ai-agent-config/config/force/document-boundaries.md) 和 [输出规范](~/ai-agent-config/config/force/document-output.md) 组织内容。以下是默认骨架及最低内容，不是固定章节或必须填满的表格；未知写缺口，不适用须有事实依据。已有总览局部维护保留原结构与范围外有效内容。

```markdown
# 运维总览

## 用途与范围

本文面向运维人员，维护本工作空间已核实服务器、运行单位及维护入口的摘要与导航。
服务器身份与连接引用以服务器清单为准；架构机制以已有架构正文为准；单位操作步骤以对应手册为准；单次执行证据在操作记录中维护。
注明实际覆盖的环境/服务器、采样时间及时区、证据来源和访问限制，相关入口使用真实路径。

## 服务器与单位
## 端口与访问入口
## 维护导航与影响摘要
## 缺口与核实状态
```

上述说明须替换成目标工作空间实际职责与来源，不把模板提示写成事实。组织以 server-id、unit-id 为主，不把同一组件在不同环境合并成一个实例。

| 内容 | 最低信息及正文归属 |
| --- | --- |
| 服务器摘要 | server-id、环境、主机名、职责及服务器清单入口；系统/容器版本、集群角色按实际需要展示，注明采样时点。连接凭据不进入总览。 |
| 单位登记 | unit-id、用途及已证实调用方、版本、部署类型、成员服务器、管理方式/执行节点、状态及证据、实际单位手册链接。Stack 与其 service 的归属可分组呈现，无须再建重复完整清单。 |
| 端口矩阵 | server-id、监听地址、端口、协议、unit-id、访问用途/暴露范围和证据；未知关联明确标注。完整网络机制引用架构正文。 |
| 维护导航 | 单位的配置/程序/数据/日志定位摘要、管理入口，以及手册中的查询、启停、升级、排障、备份恢复章节链接。特殊调度或部署机制仅说明存在、归属和入口；不重复命令册、执行顺序及成功/失败判据。 |
| 依赖与影响摘要 | 对定位故障有用的已核实依赖、方向及影响，并链接架构或单位手册。总览不维护第二份完整拓扑或机制解释；尚无正文时保留必要摘要和缺口，不虚构链接或无依据扩写。 |
| 数据与备份导航 | 数据持久化位置、备份责任单位、手册入口和恢复验证状态摘要；范围、保留策略、恢复步骤在单位手册维护。存在备份文件不能标成已可恢复。 |
| 未决与更新 | 缺失/冲突/未验证事实、受影响对象、后续核实入口；可注明最新事实更新日期及对应任务记录链接，不把完整历史操作日志复制进长期总览。 |

输出语言默认简体中文，用户或既有文档有明确约定时沿用；命令、路径和实际标识保持原样。

## 验证与边界

- 沿“服务器 → 单位 → 端口/管理入口 → 实际手册 → 对应操作或故障检查点”走读，确认读者能找到下一步；步骤正文仍由手册自足说明，不能让总览成为另一套操作规范。
- 回查主机归属、版本、端口及依赖的证据，确认没有模板服务、默认端口或未经证实的关系。未验证命令不能因写进手册链接就升级为已验证。
- 新增/移除单位或手册只更新受影响条目；单次探查未发现原有服务时先核实采样范围和权限，不自动删除其他环境或历史有效登记。
- 检查手册、架构、服务器清单及记录链接确实存在。共享事实只维护一次；总览摘要变化随其权威正文更新，不反向用过期摘要覆盖事实源。
