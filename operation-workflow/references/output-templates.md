## 填写与内容验收

实际任务统一使用 record、execution 两类分工，不按任务规模分流；其他块只用于各自长期事实/策略文档，不自动全建。接入、盘点、变更、汇报和记录的触发与授权仍由主流程维护，目录见 [工作空间](workspace.md)，历史证据与纳管见 [留痕](records.md)。内容呈现统一消费全局输出规范，下表只补运维信息的归属和最低判据，不建立另一套排版规则。

### 各产物的信息落点

| 产物与落点 | 运维专属信息及验收 |
| --- | --- |
| access：身份、连接与撤销字段 | 能区分资产身份、登录账号、运行账号和提权边界；主机密钥的本地记录与可信确认分开。连接参数可定位到完整持久来源；连接白名单对应真实接入来源和核验状态，范围内直接连接；远端动作批准不随连接放行扩大 |
| index：导航表及跨服务字段 | 每个实际单位有稳定ID及详情入口；版本与状态带证据边界。端口区分监听地址、协议、发布/目标与访问用途；未关联监听登记为未知。只概括影响和缺口，完整镜像digest、挂载与命令留在详情或确切证据入口 |
| unit：成员、路径及配置消费字段 | 多成员能逐项比较管理对象、身份、版本、状态和证据。宿主程序、Swarm service/task、Compose及独立容器分清；原定义与运行基线的漂移单独列明。配置路径到包含文件、启动入口和消费者的关系可追踪；工作目录缺失不拿配置目录或登录目录代替 |
| unit：备份与恢复现状 | 数据、日志、备份分清；命名卷、匿名卷、bind及容器可写层分别说明风险。已验证恢复须给对象/来源版本/时间/结果；缺责任人、备份链或演练时逐项登记。敏感原件仅引用受控位置，Git投影不作恢复源 |
| unit：重复操作与缺口字段 | 每个操作可定位身份、目录、精确动作、预期结果及失败出口；候选写命令与已执行查询分开。没有可用探针、恢复命令或配置生效方式时列出具体阻塞及材料，不为凑齐操作写通用重启或猜测参数 |
| record：目标与当前结论 | 先读结论、异常和待决定事项，再用导航定位具体版本、批准来源和操作。导航覆盖本记录各方案版本，待决定/异常在前，其余按方案顺序；只放短状态和具体链接，不重复方案正文、命令、长路径或哈希。历史决定保留当时效力，当前撤销/失效或新版待批不得隐藏 |
| record：方案与决定 | 读者无需阅读源码即可理解前后差异、顺序、影响、备份、验证和失败出口；这些内容在所属字段展开，不合成一段保障套话。整体批准对应明确版本和实际来源，命令allow不能冒充方案批准；方案不依赖预写命令才能批准；执行后沿操作链接核查实际命令，结果不复制原始输出 |
| record：验收与归档 | 验收标准逐项给结果；精确文件范围保留在所属正文，状态表只作关联。结果确认、归档批准、索引检查、本地提交和推送分别判断，同一答复覆盖两项时两行引用同一来源，不新增确认次数；旧批准不得覆盖新差异 |
| execution：共用上下文 | 身份、连接与策略共用一次；多目标或不同身份须逐项可定位，各操作只补差异。无远端操作明确不适用，不要求为本地文档任务造连接或命令 |
| execution：操作明细 | 一个有明确目的及失败出口的操作可包含相关命令。按命令、执行时点/退出状态、预期与实际对照、必要证据、异常的顺序核查；对照按检查点组织，不按工具调用或每条命令拆行。来源或参数等静态记录引用不另建操作；未执行的操作写预期、未执行及原因，不预写候选命令清单。中途失败、部分完成和未知不得被末尾成功掩盖；本地检查不证明远端健康 |
| execution：需求与决定来源 | 真实需求、批准/拒绝/撤销等决定只保存一次，关联具体对象和版本；有可核验持久回执或项目要求的唯一机器来源时引用，不复制原文。不默认增加消息哈希、聊天导出或独立审批文件 |

### 单位操作覆盖与条件

单位操作至少核对下列查用路径；已存在的机制给精确入口，未核实机制保留对应操作中的阻塞说明，不生成假命令。升级、扩缩容、备份和恢复有真实机制或本次需求时才增加操作条目；否则在备份现状及缺口字段登记。

| 查用路径 | 必须回答的运维问题 |
| --- | --- |
| 状态查询 | 精确管理对象、限定字段、正常基线、退出结果及采样时点是什么；是否会输出环境值或敏感参数 |
| 健康判断 | 进程/副本、协议/接口、业务或数据分别验证到哪层；探针目标、认证安全引用及预期结果是否已有证据 |
| 启停与任务变更 | 原先运行/停止状态、依赖及顺序、维护窗口和中断影响是什么；任务重建、重启与整Stack发布有何不同；缺恢复条件在哪一步停止 |
| 配置核对与生效 | 原件及包含链、修改diff、配置检查、reload/restart/重建的实际支持方式、回读及失败恢复是什么；不能用投影覆盖原件 |
| 日志定位与排障 | 后端/路径、时间窗/条数、脱敏字段与读取权限是什么；权限不足、日志超限或后端未知时如何缩小或停止采集 |
| 备份恢复或升级扩缩容（条件成立时） | 版本/存储兼容、节点放置、复制与数据一致性、备份可用性、恢复点/恢复时长要求及演练证据是什么；不可逆处和停止条件在哪 |

验收时沿“总览单位 → 实际对象 → 配置/数据 → 状态命令 → 健康层级 → 失败/恢复”走读一个宿主服务和一个容器/Stack；若环境只有一种则说明覆盖范围。逐项核对单位成员、镜像和挂载，条件不适用与信息缺失分别保留。已授权材料不足时交付具体缺口，不能以格式通过、监听存在或副本满足替代实际健康与恢复验收。

record 与 execution 各使用上方固定骨架，方案、操作和来源沿用稳定标识；只重复真实条目。没有操作时在“操作明细”下写 `条目情况：无：未执行及具体原因`，不创建空操作。尚未执行时写明确原因与预期，不为占位编写候选命令。尚未形成方案或未取得批准，在对应字段标具体缺口；已提交方案的目标和范围保持原版本，实际命令和结果在执行后按事实补充。

模板中的 `verbatim` 声明逐字来源，成品去掉模板标记并使用足够长的普通文本围栏；原文内部标题和换行不变，来源信息在围栏外。原文不可取得或不能安全保存时标缺失及影响，不用摘要冒充原文。历史材料按[留痕契约](records.md)续接，不自动迁移；模板不授权额外采集或生成附件。

检查使用共用检查器的 `--block access|index|unit|record|execution` 指定实际产物。JSON/YAML 消费既有输入契约，不套本文骨架。除结构检查外，按“当前决定/异常 → 方案版本 → 操作对照 → 决定来源 → 验收归档”查用；确认只读方案即可作出决定，导航与所属条目状态一致，操作可反向定位方案，缺证据的项没有写成通过。检查正常、待批未执行和部分失败/回退的适用状态，不能只用成功样例证明模板可用。格式检查不能验证链接目标内容、审批真实性或实际运行结果。
