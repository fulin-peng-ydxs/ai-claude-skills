# 单位运维手册契约

本文维护单位手册的只读取证、正文最低内容及验证。连接、命令和留痕必须遵循 [技能入口](../SKILL.md)，不能因生成文档取得部署或写服务器权限。

## 范围和证据

先确定 unit-id、环境、成员服务器和输出位置。单位可以是某环境的 Redis 实例、独立组件、Docker Stack 或跨主机集群；名称英文小写 kebab-case，同名组件不同环境不能覆盖。优先维护已有权威手册，无约定时放 `OPS_ROOT/units/<unit-id>.md`。

仅使用已授权范围内的只读证据：服务管理配置、进程、监听端口、容器/编排定义、限定目录内的配置与脚本、已有手册及日志。先定位安装/配置入口再追踪，禁止默认全盘扫描。具体命令按目标工具可用性选择并按统一策略审核，不把探查示例当成白名单。

进程参数、容器 inspect、配置及日志可能包含秘密，优先字段投影和脱敏。没有工具或没有权限表示证据缺失，不表示服务不存在。当前进程存在不代表业务健康，没有连接快照不代表没有长期调用。依赖须有配置引用、编排或实际调用证据，共处一台主机不能证明依赖。

## 正文参考结构与最低主题

面向运维人员，按“识别单位—找到管理入口—实施步骤—判断结果—失败恢复”组织。生成文档开头具体说明：本文维护哪个环境/单位的职责、配置和操作步骤；系统部署拓扑在架构文档、连接及命令授权在工作空间策略、历史执行在 records；附证据来源、采样时间和未验证范围。已有文档局部更新保持原结构，不套模板重排。

| 主题 | 最低内容 |
| --- | --- |
| 职责与部署 | 业务用途、调用方、版本、部署方式、成员服务器/集群角色；区分常驻服务、一次性任务、调度任务和构建工具。 |
| 路径与配置 | 程序、配置、数据、日志、备份目录；配置来源、用途、消费方、生效方式、缺失后果，必要链路使用脱敏示例。 |
| 管理与启停 | 执行主机、身份、工作目录、前置条件、精确命令、执行顺序、停止影响、成功判据、失败排查与恢复入口；命令“已发现/静态核实/实际执行验证”明确区分。 |
| 网络与健康 | 端口/协议、进程或容器特征、健康检查、业务验证、已证实的上下游依赖和故障影响。 |
| 日常维护 | 按实际机制描述查询、重启、配置生效、升级、扩缩容、日志查看；无对应机制时说明不适用，未知不能写不适用。 |
| 备份与恢复 | 备份范围、保存位置、保留策略、恢复前提、恢复步骤及验证状态；不可恢复/未测试明确说明，不把备份存在当恢复证明。 |
| 排障及约束 | 常见现象、检查路径、必要权限、失败停止条件及需要人工处理的事项；授权分类引用唯一策略，不在手册另建白名单。 |

可复用安装、升级、恢复方案与当前主机实例分区或分文件维护并互相引用；实例记录资源、路径、版本、连接策略引用和偏差，不存凭据、私钥或单次操作流水。不因为文档生成修改其他工具的全局记忆。

## 联动与验收

新增/移除单位或成员、端口、数据目录、依赖变化时，只更新受影响的手册、工作空间索引和服务器清单。总览按 [运维总览契约](operation-index.md) 维护，只保留定位摘要与手册链接；涉及部署架构机制变化时按 [工作空间架构协作](workspace.md#部署架构协作) 更新已有权威正文，不生成平行说明。

沿一条代表性操作检查读者能否识别对象、执行位置、前提、步骤、结果和失败后的下一步。路径/版本/依赖回查证据，未执行命令保留未验证状态；不为完成手册验证实际启停/部署/恢复。交付真实文件路径、主要事实、索引更新和缺口，实际探查与文档编辑均按主流程保存记录、审批和归档。
