# 方案、执行记录与归档

本文定义任务留痕与文件纳管；目录见 [工作空间](workspace.md)，授权执行见 [主流程](../SKILL.md)。记录是历史证据，不授予后续权限。Markdown 产物的通用规范统一从 [固定模板](output-templates.md) 接入。

## 审阅与执行分工

项目及运维根明确后，在 `OPS_ROOT/records/` 排他创建 Asia/Shanghai 时间目录 `YYYYMMDDHHmm`，重名追加 `-01`、`-02`；多服务器及原任务中的初始化共用记录。目录未定先收集资料，确定后补存真实来源。

实际任务统一消费[固定模板](output-templates.md)的 record、execution 块：`record.md` 是人工审阅入口，`execution.md` 是命令及来源证据的唯一明细。先记录已知目标和真实需求，不预填命令清单；操作完成后汇总真实命令、结果及必要来源，不预填成功。没有操作时明确原因，不创建虚构条目。职责不按任务规模、操作次数或复杂程度变化，不另建 plan、report 或状态台账；技能讨论和审查不触发这些运维产物。

审阅记录必须自身足以决定是否批准：保留具体前后差异、影响与保障、执行顺序及结论，不能只剩链接。精确命令、原始来源和必要输出在执行明细中保存一处；审阅记录用方案编号、操作编号和具体链接定位，不复制代码或工具流水。按固定模板从当前决定导航到方案，再到操作及批准来源；导航是所属条目状态的摘要，不形成独立台账。历史方案的当时结论保留在所属条目，新增事实更新当前摘要，不把历史流水搬回顶部。

## 版本、来源与执行关联

- 方案使用稳定编号和版本，如 `S03/v1`；操作如 `O03`，来源如 `R01`、`A01`。方案链接操作，操作反向关联方案版本；批准绑定方案及其操作范围，来源只保存一次。链接定位实际条目锚点或持久证据的具体位置，不只指向目录或整份长文；标题/路径变化同步修正关联。名称不作为批准证明，执行者仍须核实真实来源。
- 提交批准时保留方案的目标、范围、步骤及关键条件；不要求预写或冻结命令。已批准的范围不改写。新增范围或实质变化追加版本，说明差异并取得相应批准。状态、结果继续按事实更新，不计算整份可变记录的哈希；已有版本引用能可靠定位时，不为每个消息、动作或输出另算哈希。脚本审阅与可执行边界见[命令策略](command-policy.md#执行方式)。
- 人工申请遵守[全局确认机制](~/ai-agent-config/config/force/collaboration-rule.md#需要先确认时)。需求及影响授权的用户决定保留真实原文或可核验的持久回执，记录渠道及对应范围；不复制全部聊天。已有项目要求机器审批文件时引用其唯一来源，不再抄写一份原文。原文内部标题和换行不改写，时间不明不猜测，缺失和脱敏如实说明；秘密不进入记录。
- 执行以能独立判断结果和失败出口的操作单元组织，例如“核对挂载”可包含几条关联命令。不同目标、授权或失败会阻断后续的动作须可分别核对，不能合并后隐去中途失败。身份、连接、策略版本等共用信息保存一次，操作只补差异；具体字段由 execution 模板维护。
- 策略须在执行前核对；一组操作记录共同适用的版本、判定及批准覆盖关系，deny、例外或新增范围单列。不为每个 checker 调用保存 JSON，不为本地排版、解析及工具包装步骤建执行流水。
- 每个操作完成后汇总实际命令/参数、所用入口版本及结果，关联方案范围，不补造执行前命令清单。参数记真实取值；影响目标、范围或实质风险的变化先补充决定，不能事后改方案来匹配执行。当次命令答复的适用条件按[主流程审批判定](../SKILL.md#审批判定)处理；执行明细关联真实答复来源与执行结果，不另建批准文件，也不把方案批准当作命令已经确认。
- 操作结果形成即保存时点、退出状态及支持判断的关键输出；失败、部分完成、跳过和未知分别说明。保留关键失败证据及实际恢复状态，不靠最后一条命令成功推断全组成功。只记录有助判断的输出，不默认保存全量成功输出和轮询流水；若采用外部证据，须持久可定位，不能让正式记录依赖临时目录。

## 附件与既有记录

附件只用于不能由两份正文替代的需要：有交付/复用价值或需固定执行内容的脚本、确需独立复核的原始证据、合规基线/镜像，或有效项目契约及实际程序必须消费的机器文件。写清用途和对应操作，不按执行轮次创建文件。脚本只保存一个正文，记录引用路径与版本/哈希，不另抄源码；未采用草稿、临时解析和一次性辅助产物进入项目约定的忽略目录。

既有记录、独立方案/报告及审批 JSON 保留可信原文和已批准版本，不因技能更新自动删除、改写或批量迁移。续接时在原人工入口说明当前状态，新增操作明细按新分工记录并关联既有批准来源；旧文档局部更新保留有效结构，不强迫全文套新模板。明确获准整理历史材料时另行核对原文、批准内容和引用的保留。

## 文件镜像

- 仅纳管任务相关普通文件，原始大小须 **≤15,000,000 字节**。传输前后核验类型、大小、敏感性及漂移；超限、大小未知、秘密/数据备份不纳入内容，不靠压缩、分片、LFS 或脱敏变小绕过。超限只记元数据，不为算哈希读全文。
- 安全原件 `/etc/nginx/nginx.conf` 映射到 `servers/<server-id>/rootfs/etc/nginx/nginx.conf`；脱敏件加 `.redacted`，字段摘要加 `.summary.md`，不得用原配置名保存不可部署的投影。拒绝 `..`、跨 server-id 和本地祖先软链接逃逸。
- 软链接只记目标/元数据；设备、socket、FIFO、数据库数据目录不复制。私钥、密码、Token 和敏感原件即使很小也不进 Git。
- 首次修改前将合规基线存到本次 `baseline/<server-id>/rootfs/...`；已有 Git 基线仍核对远端漂移。最终回读写镜像，删除登记 tombstone；基线、附件和日志遵守相同大小/脱敏要求。
- 镜像不是完整备份，恢复所需权限/属主/ACL 等另记。真实备份按单位手册的受控位置维护；必要备份未验证时停止依赖变更。

## 结果审批与提交

完成回读、敏感信息检查和映射，在审阅记录汇总实际结果及精确拟提交范围；审批触发和覆盖范围统一消费[主流程的审批判定](../SKILL.md#审批判定)。拒绝/待补充保留待处理状态，不自动回滚或抹掉失败证据。

保留用户改动，不擅自 stash/reset；无关 staged 不得混入。提交范围只包含审阅/执行记录及已说明用途的实际附件、手册和镜像，不附带临时产物。批准后仅暂存明确文件，不用 `git add .` 代替范围确认，然后运行：

```bash
python3 <技能目录>/scripts/check_archive.py index --repo <仓库根> --operations-root <仓库相对运维目录>
```

检查覆盖运维目录整个索引快照的路径、对象类型和大小，不检查脱敏、原始大小或审批真实性；这些人工核对。超限历史文件先取得处置授权，不擅自删远端或重写历史；记录过大转受控外部归档，不截断原文。

复用提交消息技能，核对 hooks/filters 等隐式动作，再提交获批内容并回查一致性。报告 commit ID，不在提交内预写自身哈希，也不为记录它反复 amend。Git 失败只标归档未完成，不自动回滚服务器；push 单独授权。
