# 统一命令策略契约

本文维护与 AI 工具无关的命令分类方式及初始化模板；每个工作空间的实际规则只在其 `command-policy.md` 维护。本文是初始参考，不是对任何服务器的授权；执行流程见 [技能入口](../SKILL.md)。

## 判定与授权

每次执行先确定完整动作：服务器/环境、身份、工作目录、可执行程序及参数、输入/脚本内容、读写对象和路径、网络目标、输出去向及副作用。文件编辑、上传下载、数据库 SQL、MCP/API 调用与 shell 等效动作统一判定。

优先级固定为 **deny → ask → allow → 未匹配 ask**；匹配多条按最严格决定，不能依赖文本行顺序。参数不明、目标变化、脚本未审、工具行为不明时按 ask，并先解释或检查到足够明确才能批准。有效运行环境的额外禁止规则仍必须遵守。

- `deny`：停止该动作，说明命中规则和替代方式。普通“执行本任务”或方案审批不能覆盖；确需变更策略时由有权人员单独审批策略差异，再重新评估任务，不得执行者自批例外。
- `ask`：人工确认具体动作及副作用；可把多条精确命令绑定到一个方案版本审批，不要求重复逐条弹窗。已获授权精确覆盖时复用。
- `allow`：仅在有效连接授权、规则范围和参数约束内可直接执行；不是无限会话或任意主机授权。
- 空策略、缺少字段、不可读取、无法判定时不放行。能明确行为且无 deny 时，可取得针对具体操作的人工授权；不能临时把未知命令加到白名单来省略审批。

命令不能只按前缀或字符串包含判断：检查 `ssh` 内层命令、sudo 后身份、管道各段、`&&`/`;`、重定向、命令替换、解释器 `-c`、脚本内容、别名/函数和工具插件。不可见的动态脚本不能当作白名单；审批脚本时绑定内容哈希，执行前变更则原审批不覆盖。读取日志/配置前评估凭据和个人信息暴露，输出在进入对话/日志前最小化与脱敏。

## 工作空间策略模板（默认骨架）

生成 `command-policy.md` 时填入以下内容，章节可合并，规则表字段不可缺失：

```markdown
# 运维命令策略

用途与归属：本文是本工作空间命令及等效工具操作分类的唯一权威来源；连接策略在 access-policy.md，具体授权和执行证据在 records/。AI 工具不得维护独立放宽的副本。

## 策略范围与版本

记录版本、适用环境/服务器/单位、维护人、审批来源和生效时间。未确认初版明确标为待确认；此时 allow 为空，远端动作必须取得具体授权。

## 判定规则

deny 优先于 ask，ask 优先于 allow；未匹配或不确定一律 ask。批准任务不等于批准修改策略。

未批准任何条目时明确写“空；无预授权白名单”，不得填入可直接生效的示例。

## 执行保障与验证状态

记录当前 AI 入口如何读取本文、运行账号权限、可用审批渠道；有工具规则/堡垒机适配时注明策略版本/哈希及验证证据。未验证的硬拦截明确标为未验证。
```

初始化时按目标环境向人提交以下分类建议，不能把建议当成已批准白名单：

| 分类 | 建议覆盖的行为 |
| --- | --- |
| deny | 擦除整盘/根目录等灾难性清除、关闭审计或主机身份校验以绕过门禁、泄露凭据、绕过审批；具体目标和动作须在工作空间写清。 |
| ask | 文件增删改/权限/属主、启停重载扩缩容、部署升级/包安装、主机重启关机、进程终止、防火墙/账号/网络变更、SQL 写入、备份恢复、未知命令及敏感或高负载查询。 |
| allow 候选 | 限定目标的身份、版本、状态、端口和健康查询；限定条数、字段和时间窗的脱敏日志读取。逐条核实后批准，不笼统批准 cat、docker、systemctl、ssh、sudo 或解释器。 |

批准的本地留痕目录写入、精确 Git add/commit 范围单独归入执行/结果审批，不等同于远端白名单；Git hooks、filters、签名程序或其他隐式执行也须核实，发现额外副作用时重新评估。

## 跨 AI 工具兼容与有效性

所有 AI 从工作空间 AGENTS 指向的同一策略读取，Claude 薄入口也指向它。无技能自动发现或专用审批工具时可显式加载入口并用普通对话完成授权；不能把政策复制进某工具私有配置后独立维护。

如需要工具级硬拦截，适配器只能从权威策略生成/引用配置，并记录源版本/哈希；生成配置注明不可手工维护。适配器不能降低限制；表达不了规则时要求人工审批或受限账号执行，不能扩大 allow。运行环境不支持拦截时，文档兼容不等于硬隔离有效；不得宣称所有 AI 工具已通过拦截验证。

核验采用无害测试环境中的允许、需确认、拒绝及远端包装/复合命令案例。不得为了验证 deny 真正在生产执行破坏操作。最低检查场景：授权内状态查询可行、同命令的 restart 不自动放行、`ssh host '...'` 不绕过内层策略、读取后重定向写入不算纯只读、文件编辑/API 写入与 shell 同等受控。
