# 运维操作

## 职责与边界

本技能维护执行顺序和授权节点。[工作空间](references/workspace.md) 定义初始化、清单和手册；[命令策略](references/command-policy.md) 定义场景默认行为、例外模式、通配写法及分类结果处理；[宿主接入](references/host-integration.md) 定义Hook注册、命令确认衔接与通道验证；[留痕](references/records.md) 定义审阅与执行证据的分工、关联和归档。环境事实保存在目标项目。

## 输入与前置条件

确定项目目录、环境、服务器/服务、目标及成功标准。初始化须明确各服务对应的源码路径，按工作空间要求核实并记入单位手册。优先复用会话、清单和手册，只追问缺项。

## 执行流程

根据任务选择执行分支：

- 讨论、审查技能或方案：对话交付，不连接、不创建操作记录。
- 空项目、无服务器资料、目标未接入或必要入口/策略缺失：先按工作空间初始化；其中当前宿主Hook接入与实测是首次服务器操作的前置步骤，资料不足待补充，空模板不能冒充完成。
- 已有证据足够的本地文档维护：完成下方共用准备后更新受影响文件，进入汇报归档，不执行远端步骤。
- 只读排查/盘点：白名单连接 → 按命令分类采集 → 汇报归档。
- 服务器改动：白名单连接检查 → 变更方案 → 批准执行 → 验证汇报 → 归档。

实际任务先读取目标策略、相关手册及[留痕要求](references/records.md)，检查 Git 基线。统一用 `record.md` 承载人工审阅，用 `execution.md` 承载命令明细与来源证据；职责固定，不按任务规模或复杂程度切换结构。人工确认前读取 [全局协作规则“需要先确认时”](~/ai-agent-config/config/force/collaboration-rule.md#需要先确认时)，确认渠道、降级和答复效力统一遵守该入口。初始化及维护手册时读取工作空间要求，只补任务需要的事实。

执行服务器操作前，遇到首次初始化、首次换用其他宿主或Hook注册/执行通道变化时，先完成[初始化接入步骤](references/host-integration.md#初始化接入步骤)；已有项目只补对应接入，不重新初始化清单或盘点其他目标。已验证且未变化的同一通道直接复用；配置存在不能代替实际接入结果。

1. **定位连接与检查范围**：读取连接白名单，核对服务器、地址/端口、账号、渠道、凭据引用与可信主机指纹。新目标先根据用户提供的资料登记并核验，缺少可信身份信息时只补齐缺项。在审阅记录写清检查目标及边界，执行时再准备具体命令，按下方审批判定继续或停止。
2. **检查并判断**：核验主机、账号和环境，读取[命令选择与权限规范](references/command-policy.md)并选等效原生查询。按[判定结果与下一动作](references/command-policy.md#判定结果与下一动作)核对分类结果，停止分支先恢复前提或报告缺口，其余按下方审批判定执行获准检查。以有明确目的的操作单元保存必要结果，证据足以决定下一步时停止采集；补充诊断只确认新增范围，不因重连重复索权。审阅记录只更新结论与证据链接。只读任务完成后进入第 5 步。
3. **提出可审阅变更**：说明目标、对象、前后差异、操作步骤、影响、备份、验证及失败出口，申请该方案范围的批准；不预写或冻结具体命令清单。先复用既有维护入口，按[执行方式](references/command-policy.md#执行方式)判断是否确需脚本。方案批准覆盖目标及操作范围，方案变化只确认新增差异。
4. **实施并验证**：复核目标及关键基线，漂移影响方案时暂停；必要备份验证后，执行当次再生成具体命令或工具参数，按下方审批判定处理allow、ask和deny。仅普通ask在执行过程中取得本次命令的明确答复后执行原命令；异常先按命令策略恢复前提或报告缺口；不因Hook缺少原生ask就把任务改成预批命令清单。每个操作完成后在execution.md汇总实际命令、结果和必要证据，record.md保留结论及链接。按成功标准核对实际状态与业务；失败先停止依赖步骤，核实已完成动作，再执行具备条件且获批的回退。结果未知不盲目重试。回读并更新受影响镜像和手册，审阅记录写实际结论及未完成项。
5. **汇报并取得结果确认**：直接展示审阅记录中的结果、失败/未验证项、文档/镜像差异及精确拟提交范围，申请结果与归档提交确认，不复制报告或工具流水。只读任务明确无服务器变更。待确认不妨碍保存证据，也不触发自动回滚。
6. **归档提交**：核对获批内容没有漂移，按留痕门禁暂存精确范围；复用 `git-commit-message-authoring` 生成消息，再本地提交。push 另需明确授权。审批后出现新差异先补充确认，不覆盖获批内容。

## 核心约束

- 连接按 access-policy 中白名单持续生效，遵守用户明确设置的期限、渠道及撤销限制；范围内连接和重连不再确认。身份不符、指纹变化或记录不完整时停止核实；白名单仅放行连接，SSH携带的命令仍单独判定。
- 凭据只用安全引用；主机密钥从可信来源核验，不关闭校验、不默认提权。只读也须限定敏感字段、输出量和资源开销。
- 策略脚本只读配置和命令文本，不执行命令、不验证审批真伪、不提供系统级隔离；包装命令和脚本的审阅及当前可执行边界见[命令策略](references/command-policy.md#传输与包装边界)。

### 审批判定

本节唯一维护运维任务的审批触发及批准范围；命令规范只负责分类，留痕和模板只负责保存与呈现。先处理禁止与异常，命令权限和任务批准条件须同时满足，不按表格首个命中项放行。确认渠道、答复效力和授权复用统一消费上述全局确认机制；平台执行权限另行核对，不用任务批准代替。

| 条件 | 决定与范围 |
| --- | --- |
| 连接命中有效白名单且身份核验通过 | 直接连接或重连，不逐次审批；连接放行不包含远端动作 |
| 任务范围内只读查询为allow | 直接执行，不为查询另批方案 |
| 命令为普通ask，且已排除命令策略定义的停止分支 | 执行当次展示目标、具体命令、用途和影响，取得明确答复后仅执行本次原命令；拒绝、取消、沉默或修改命令则不执行。原生ask、AI问询及重试核验按[宿主接入](references/host-integration.md#适配与命令确认)处理，工具不可用时按全局规则降级；不能凭AI标签自行放行 |
| 服务器变更，无论命令allow或ask | 先批准具体方案目标及范围，涵盖实施、验证和条件回退；方案不要求提前列出具体命令，文件工具、上传下载、SQL/API按实际副作用同判，不按命令条数或任务复杂度分流 |
| deny，或命令策略判为停止分支、必要前提不明 | 按[判定结果与下一动作](references/command-policy.md#判定结果与下一动作)停止、恢复/核实或报告当前不支持；普通批准不能覆盖deny或代替必要前提 |
| 范围、身份、前提或实质风险变化；既有策略权限放宽 | 只确认未被已有授权覆盖的差异；初始化采用技能默认基线按工作空间规则处理 |
| 结果确认与本地归档 | 展示实际结果和精确文件范围后可一次共同确认；执行批准不自动覆盖结果或归档 |
| push | 必须有明确覆盖推送的授权，已有则复用 |

## 产出边界与交付

以 `record.md` 为人工入口，`execution.md` 为可追查的执行明细；必要手册/镜像按事实变化更新。方案与报告不另起文件，脚本、原始日志和审批 JSON 不作为默认产物。文件触发、关联和历史保留按[留痕](references/records.md)执行；分别说明服务器结果、人工确认、归档和 Git 状态。

新建或整体重构 Markdown 运维产物前读取 [固定产物模板](references/output-templates.md)，按实际交付块填充。原文保存和局部更新保留基线；既有授权、命令策略及归档门禁继续执行。

## 验证与完成标准

失败/取消保留证据，未完成审批或提交不称完整闭环；未做业务检查不称业务验收通过。

交付前按模板的审阅路径走读：

1. 从 `record.md` 顶部找到当前决定和异常，定位具体方案版本；只读该方案即可判断改动、影响、保障及是否批准。
2. 沿操作链接到 `execution.md` 核对命令、预期与实际、证据及真实批准来源，并能反向回到方案。
3. 分别核对归档状态，不以执行批准代替结果确认或提交批准；检查未执行和失败没有冒充成功，附件都有实际用途。

归档前运行索引检查：

```bash
python3 <技能目录>/scripts/check_archive.py index \
  --repo <仓库根> \
  --operations-root <仓库相对运维目录>
```

该检查仅覆盖索引路径、类型和大小，不能替代敏感信息、授权或远端结果核实。

完整生成或整体重构运维产物后，运行模板检查：

```bash
python3 <skills-root>/skill-authoring-standard/scripts/validate_document_template.py \
  <产物路径> \
  --template <本技能目录>/references/output-templates.md \
  --block <实际产物块>
```

格式检查不能代替授权、内容及实际运行结果核实。
