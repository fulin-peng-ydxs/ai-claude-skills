# 任务界面交互设计清单

用于桌面和移动端任务界面的新建、重构及局部修改。按当前任务读取相关章节；通用部分不以移动目标为前提，触摸与原生输入部分仅在相关能力受影响时读取。具体布局、数值和策略来自项目契约或已确认的设计决策。

## 通用任务与状态

### 任务、层级与密度

- 调整布局前识别用户当前要完成的核心操作、服务该任务的辅助配置及结果查看，核对现有入口、操作频率和当前值的可见性。分区名称与位置应让用户预测功能所在；不把操作、解释和结果平铺成同等层级，也不强制采用固定栏数。
- 将控件移入菜单、合并入口或改为跨页操作时，比较改动前后的发现成本、点击层级和上下文切换。减少屏幕元素不是充分理由；核心操作的收起或迁移须符合已授权目标，并保留必要的当前值与状态线索。
- 参考成熟系统时，选择同类任务对照区域职责、入口到结果的路径及状态承接；明确哪些模式适用、哪些因业务差异需调整。项目专属的位置和布局选择留在项目设计契约，不从参考截图推导通用固定布局。

- 根据项目支持的视口、输入方式和高频任务组织界面。相关短字段仅在字段值和错误信息均可容纳时组合排布。
- 区分主要提交、工具操作、可编辑条件和输入字段。较大的操作命中区不要求同样大的可见控件底板；降低视觉体量时仍须保证操作可达。
- 区分改变数据范围的条件与改变分组、排序或读数方式的展示工具，名称、分组及当前值应帮助用户预测影响。只有一个有效选项时，判断是否仍需要选择入口，不能为保持工具栏形式制造无效操作。
- 根据控件角色及周围线索选择边框和背景，不因元素可点击就机械添加。独立命令可能需要可见底板；分组清楚的行或标题工具可通过标签、展开或跳转标识、按下反馈表达可操作性。避免所有控件都有边框，也避免为视觉简洁消除操作线索。
- 评估标题、筛选、操作、导航和安全区占用后剩余的正文空间。优先合并重复标题、帮助文本和次要信息，再考虑缩小文字或命中区。
- 使用真实的长值、多条件筛选、错误及适用的输入状态检查布局。分组标题与标记应传达任务；改善层级时保留必要的分组功能。

### 滚动归属与固定区域

- 明确页面及各弹层的滚动归属，以及有意固定的区域。在内容顶部、中部和末端验证边界；是否固定属于产品决策，不要求所有页头固定。
- 明确操作区参与布局还是覆盖内容，吸附定位时也须判断。仅预留使内容可达所需的空间，导航与安全区只计算一次；已由布局分配的空间，不再添加覆盖占位。检查末项、展开字段、底部空隙、透明区域点击，以及短内容和长内容。
- 区分原生惯性、局部边界反馈、滚动传递和外层页面移动。修复非预期的外层移动时，不让正常滚动变得生硬；除非交互确有需要，避免自行模拟触摸物理效果。
- 滚动位置提示应位于所属滚动区域内，避开操作路径。同角色提示采用一致的显隐和消退时机，离开后不残留。
- 长列表区分内容裁切和数据数量限制。按任务选择滚动、分页或渐进加载，并展示真实的后续浏览状态。清楚的分页控件不需要额外文字解释如何翻页；数量或搜索提示只用于解决实际限制或歧义。末尾区域对齐与控件样式应和同类列表一致。

### 对齐与控件角色

- 分别比较控件外框、文字内缩、帮助或错误文本、基线及文字垂直中心。外框一致不代表文字对齐。原生控件的额外检查见后文。
- 按数字的角色选择对齐方式：连续编辑和跨行比较的需求不同。为每种角色定义一致约定，不把所有数字强制对齐到同一侧。
- 比较各使用点中同角色控件的默认、禁用、加载和错误态。检查继承样式及响应式覆盖，不只依赖共享 class 名称。
- 同一任务的新建、编辑及补充流程按操作角色比较入口、主次顺序和可达性；需要固定操作区时沿用相应布局约定，不因进入弹层就改变操作路径，也不把不同任务强制做成同一布局。
- 分别设计编辑态与阅读态：仅服务编辑、且信息已被标题、分组或正文表达的分类选择、填写提示和必填标记在阅读时隐藏；唯一业务信息转为静态展示，保留完整值、单位、关系及必要阅读操作，避免换成另一套重复标签或留下空工具区。保存中等临时禁用与权限受限按实际任务另行判断，不因控件只读就一律保留或隐藏。

### 直接操作与排序

- 可调整顺序的列表按频率、列表规模和输入方式选择拖动、位置选择或移动命令，不为减少按钮而引入难以发现的手势。采用拖动时，明确操作入口、有效目标和落点反馈，并提供目标用户可用的非拖动路径；不要求所有排序都用拖动，也不要求替代入口常驻每一行。
- 区分预览顺序与已保存顺序，设计取消、保存中及失败后的状态。分组、分页或筛选列表应说明可调整的范围，不能让局部重排暗示已修改完整列表；允许范围来自业务契约，不由视觉方案决定。

### 输入与弹层

- 分别设计焦点、展开、选中与按下反馈；原生选择结束后不为消除高亮强制失焦。指针、触摸和键盘的反馈可按角色不同，但不能以全局隐藏键盘焦点或统一调用 focus/blur 代替状态设计。
- 复合控件明确当前操作由入口、内部输入还是内部动作承接，避免入口与搜索输入重复强调；保留内部按钮自身必要的键盘焦点。弹层初始焦点按任务、内容和误操作风险选择，关闭后的恢复不得覆盖用户已交接到的新任务。
- 将候选浏览、临时搜索、当前选值和已确认的表单值作为不同状态设计。覆盖打开、选择、取消、字段交接和页面导航，避免提前修改选值。
- 区分取消临时搜索和清除已确认选值。恢复操作应无需滚完整个长候选列表即可发现；位置与展开方向以交互契约为准，不统一要求顶部操作行或向下展开。
- 根据实际可见视口与所属容器的裁切边界、固定区域占用确定可用空间；需要滚动让位时以真实可滚动范围为限。键盘、异步内容及过渡改变几何位置后应重新适配，避免定位与滚动修正互相触发而反复缩小或跳动。检查完整候选行、内部滚动与操作可达性；外框未越界但内部内容被裁切，仍不算完成。
- 按任务确定关闭按钮、外部点按、返回及键盘取消各自的退出语义；同一退出意图共享未保存与提交中保护，不统一要求所有弹层允许外部关闭。辅助子流程取消后回到仍有效的原任务，保留约定的草稿、位置和焦点；父实体已失效或任务已结束时返回有效入口，避免重开过时详情。
- 嵌套表单的离开确认只针对本次退出会影响的内容，关闭子层不应清除父层草稿。辅助操作使用已保存值还是当前编辑值须明确，避免用户误以为未提交内容已参与操作。

### 图表与瞬态反馈

- 根据输入方式确定读数、选择与下钻入口，再选择图表效果。标签、固定读数或主动选择能提升可读性时再采用，不要求所有图表使用同一种模式。
- 指标与解释应明确对应整个范围还是局部选择，入口靠近其解释对象。辅助信息按阅读频率、长度和是否需要同时对照正文，选择就地说明、展开或弹层；不以折叠项数量决定承载方式。无数据、不可计算与真实零值分别表达，避免占位指标挤占主要读数。
- 按适用场景明确瞬态反馈的结束条件：指针离开、焦点离开、主动关闭、页面隐藏或数据变化。覆盖项目支持的输入方式。
- 根据影响范围、严重程度、阻断程度和恢复动作决定提示位置。字段错误靠近对应字段；页面级次要信息可放稳定的状态或标题区域，按需展开详情；阻断性失败须有可达的恢复路径。避免每条提示都变成警告块或模态弹窗。消息应适配空间、不遮挡操作或推移无关区域，并保留符合其角色的阅读时间；常规成功反馈可自动结束，恢复动作可能需要持续保留。存在弹层时，消息及恢复动作在当前交互层仍须可见、可达，辅助层关闭后按剩余任务承接。条件帮助文本在需要保持布局连续性时使用稳定空间。
- 保留卡片层级，不为重复数量和操作行浪费正文空间。次要信息与相关数值对齐能提升扫描效率时再采用，不统一规定一种卡片排列。

### 数字展示与语义颜色

- 展示精度与计算、存储分别约定。产品省略冗余全零小数时，金额、单价、数量和百分比按约定一致处理，不舍弃有效精度或改写尚未完成的输入。设计修改遵循项目格式化契约，不改变计算与存储规则；格式化实现的精度和复用由代码审核承接。
- 数字颜色来自领域含义，并结合邻近标签、图例及符号判断所需强调；符号与数值共同表达同一含义时，不能仅靠细小符号着色承担辨识。明确语义范围后再选择强调方式，不统一要求所有数值着色。比较支持主题下的摘要、卡片、排行和图表读数；检查计算后的实际颜色，局部选择器优先级可能覆盖预期语义 class。标签和控件保持各自视觉角色，必要时保留非颜色线索。
- 对比度需要时，区分语义强调色、可读文字色及色块内部前景色。各主题复用项目 token 角色，不将一种颜色强行用于文字、图标填充和描边；警告色的具体色相由产品约定。

### 文案与恢复

- 说明哪些内容已保存、哪些未保存，以及用户下一步能做什么。区分本地备份失败和主操作失败；实现术语只有在帮助用户行动时才呈现。
- 同类场景的标签、搜索提示及动作名称保持一致。有实际含义差异时解释差异，不机械地给不同操作使用相同文案。
- 按钮以动作及对象为主；附加说明按需要放在就近帮助、执行前确认或结果反馈中。会影响用户决定的后果应在执行前可见，成功提示只承接结果，不为缩短按钮文案而新增无必要的确认弹窗。
- 可选草稿或客户端辅助能力因访问环境、权限或能力限制不可用时，设计明确反馈与恢复路径，避免主操作无反馈失效。环境证据按共用验证方法判断。

### 导航与任务连续性

- 明确离开页面时保留、关闭或暂停哪些内容。辅助流程应返回原任务，并保留约定的草稿、条件和滚动位置；隐藏页面不得保留活动弹层或抢占焦点。
- 区分首次进入、缓存 tab 返回、明确的详情或下钻返回，以及数据刷新。位置来源只在对应转换中生效，旧返回参数不得反复覆盖用户最新滚动位置。内容就绪后再恢复；延迟操作须防止影响已变化的路由、非活动页面或更新的请求。
- 为来源标记、临时筛选与返回入口明确结束条件。按契约区分重置查询、结束来源任务和普通导航；来源上下文结束后移除对应入口，记忆的页面地址不应让过期返回路径复活，不统一规定清除筛选必然结束来源。

## 触摸与原生输入

仅在目标输入方式或原生能力受影响时使用；混合输入设备保留键盘及指针路径。

- 移动目标按项目最窄支持视口验证可操作空间，不只是缩小桌面页面。原生日期、时间和选择控件检查目标平台的实际文字位置与操作路径。
- 分别处理焦点、键盘出现和视口缩放。采用适合目标平台的控件，防止非预期的点击或聚焦缩放，同时保留无障碍缩放能力；不通过全局禁用缩放掩盖布局问题。
- 同时设计键盘展开与收起后的恢复。在所属滚动容器内使当前字段可见，收起时保留有效阅读位置；延迟执行的视口或滚动修复须防止影响新的焦点会话或非活动页面。重置所有滚动位置不是通用修复方法。
- 明确点击、长按、拖动和原生文本选择之间的关系。开始滚动时取消待触发长按，避免拖动结束变成点击；仅靠手势的命令须提供可发现的替代入口。不因目标是移动端就引入滑动操作。
- 原生选词或操作菜单与按钮、卡片操作冲突时，仅在相应目标内限制，保留可编辑字段及用户需要复制的文本。分别诊断选区、点击高亮和焦点边框，避免全局移除键盘焦点标识。
- 图表读数不能仅依赖 hover；触摸与键盘用户都应有可用入口。
- 实测从图表区域开始拖动并滚动页面。滚动意图不应误触数据选择、导航或提交；读数避开手指遮挡和固定控件。

## 安装态与缓存

仅在项目使用安装、离线或缓存能力且本次受影响时，明确安装态的导航、恢复、更新与失败反馈。实际加载版本和终端证据按 [前端验证规范](~/ai-agent-config/config/force/frontend-verification.md) 处理。
