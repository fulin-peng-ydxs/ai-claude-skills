## 填写与内容验收

## 核心内容

以下解释固定槽位的填写要求：

| 内容 | 最低要求 |
| --- | --- |
| 定位与能力 | 解决的问题、主要读者、运行形态、适用边界；能力连接场景、入口和产出，不能把规划能力写成现有能力 |
| 首次使用 | 必要版本与依赖、执行目录、必要配置与数据准备、安装/启动或调用、可观察结果；长期服务说明停止和清理 |
| 使用说明 | 至少一条从入口到结果的真实使用路径，避免重复安装步骤；示例对应当前 API、页面、CLI 或包入口 |
| 开发与验证 | 项目实际提供的测试、静态检查、格式化、构建或打包入口，说明范围、目录和成功判据；命令及其执行条件复用项目权威来源，不独立维护或重复验证 |
| 代码定位与结构摘要 | 按需要概括运行单元、主要依赖和目录职责，以精简目录树或表格定位页面、接口、业务逻辑、数据、配置、测试或部署入口，不穷举文件；深入关系按上述边界引用架构正文 |
| 文档导航 | 真实存在的权威入口及各自职责；没有独立专题时明确当前归属，不编造链接 |

纯文档、静态资源等没有安装或启动过程的项目，说明获取、查看或使用产物的路径及不存在相关命令的事实。缺少某类开发工具时说明实际情况，不编造替代能力。未知不能当作不适用。

## 项目目录与展开深度

目录展开以能定位主要开发职责为准：

- 在结构与依赖摘要中展示仓库主要目录及其职责子目录，通常到第 2–3 层（仓库根为第 0 层），覆盖实际存在的主要业务模块、共享能力、配置、测试、工具和文档入口；不只列 `backend/`、`frontend/` 等外壳目录。
- 大型模块或 Monorepo 按需继续展开，直到能区分页面、接口、服务、领域逻辑和存储等职责；小项目可更浅，不强制所有分支同深，也不把层数当作截断重要模块的上限。
- 展示项附简短用途，关键启动、配置和构建文件按需列出；不穷举源码文件，不展开依赖、缓存、构建产物和运行数据内部。详细调用关系与实现机制仍归架构正文。

## 文档引用与协作说明

只引用支持读者使用、开发或深入理解的当前有效入口，并说明用途；导航不作为全量文档清单，编写时读取过的材料也不必全部引用。

| 对象 | 引用边界 |
| --- | --- |
| 项目命令与协作规则 | 复用命令时注明 AGENTS 或其声明的命令正文来源；详细协作规则链接项目权威入口，CLAUDE 等工具薄入口按需列出 |
| 架构、模块、配置、API 与运维说明 | 读者需要深入理解或执行任务时引用，优先链接主入口或相关章节，不平铺所有下级文档 |
| 设计、测试、贡献与许可证 | 按项目实际适用情况链接对应权威文件；执行任务需要的前提与最小步骤仍在 README 就地说明 |
| 需求闭环、需求文档、开发计划及阶段记录 | 遵循全局协作约束，不纳入长期导航，不作为当前事实来源 |
| 个人全局规范、技能安装文件、临时或退役材料 | 不作为项目 README 的常规引用入口，不复制本机路径或内部生成流程 |

协作说明通常只需交代规则入口及用途，不复制协作细则。同一入口可集中导航，任务旁保留必要的就近链接；不在导语、各章节和页尾反复列同一套清单。缺少独立文档时说明当前归属，不为满足导航新建文档。

## 条件内容与深度

仅在代码、配置、文档或用户要求触发时补充，放在上方固定任务字段或共享槽位：

| 触发条件 | 应写内容 | 深入内容归属 |
| --- | --- | --- |
| 暴露 API、SDK、CLI | 最小输入输出示例及调用入口 | 完整契约引用实际 API/SDK 文档 |
| 非默认配置或秘密来源 | 必填项、默认行为、配置来源和敏感信息边界 | 覆盖优先级与消费机制归技术专题 |
| 数据库、模型、初始化或迁移 | 首次使用必需准备、执行顺序、成功判据和数据影响 | 完整迁移机制或运行操作引用对应专题 |
| 正式部署与发布材料 | 产物、发布入口、健康检查、日志及停止/回滚入口 | 部署机制归部署架构，具体环境操作归运维手册 |
| 可证实的常见故障 | 现象、检查顺序、日志入口和恢复方式 | 复杂排障引用维护文档 |
| 明确兼容范围 | 运行时、框架、平台或协议兼容关系及依据 | 详细兼容机制归技术专题 |
| 已有贡献规则 | 必要协作流程和不可破坏的边界摘要 | 权威规则归项目协作文件 |
| 许可证、第三方资产或引用义务 | 文件入口与必要归属 | 不自行推定授权范围 |

项目类型决定重点：应用写角色与最小业务结果；服务写请求或任务；库/SDK 写导入、公共 API 和扩展边界；CLI 写参数、输入和产物；Monorepo 写子项目组合、工作目录及构建顺序。混合项目围绕主交付形态补差异，不另起重复章节。

截图、演示与账号获取方式服务使用路径，不编造账号或默认初始化。技术版本就近放在运行前提或架构摘要，路线图和维护状态须有权威来源，变更记录只链接当前 changelog。

## 开发者路径与更新检查

- 全栈或多服务项目说明启动哪些进程、哪些依赖须先准备、访问地址、请求如何到达后端及如何停止。集成启动与独立调试、日志或断点入口按实际能力说明，未经执行的 IDE 操作不得称为实测。
- 以使用或开发任务为单元，将入口、前提、步骤、结果和失败检查放在一起；共用配置与兼容关系集中维护，任务补差异。复杂关系才使用 Mermaid，图、表和文字不重复表达同一内容。
- 更新保留有效项目特性和已有结构；获准重构时才合并或重排，并修复变更标题的入链。删除过期事实、空章、占位内容、宣传语、历史流水和复制的专题正文。
- 检查文件、目录、端口、版本与仓库事实；相对链接必须存在。表格避免过宽，代码块标注语言，命令解释放在块外。
- README 可就地展示最小操作所需的命令片段，须保留来源中的参数、执行目录、前提、成功判据及适用的停止方式，不复制完整命令目录或 AI 协作规则。需要不同参数或新命令时交上游技能维护，不在 README 中派生第二套定义。
- 按技能入口执行结构校验，报告复用来源、上游补齐结果和内容检查。沿首次使用路径能找到下一步和成功判据，才说明入口内容完整；纸面走读或格式通过不证明本次执行过命令。
