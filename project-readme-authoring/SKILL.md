# 项目 README 编写

## 职责与边界

README 是项目使用与开发的主入口，回答“这是什么、如何开始、常用任务怎么做、深入内容在哪里”。本文维护执行流程与命令来源接入；[输出契约](references/output-contract.md) 维护内容与读者检查。

项目命令的发现、验证与权威文档维护统一由 [AI 约束文档编写](../ai-constraint-doc-authoring/SKILL.md) 承担。README 从该技能维护的 `AGENTS.md` 及其明确指向的命令事实源获取内容，不自行推导、执行验证或维护第二套验证门禁；`CLAUDE.md` 只用于定位权威入口。

技术机制由模块/技术专题文档维护，逐环节状态、权限与数据规则由业务闭环文档维护，交付完整性和接手风险由接手报告维护。README 保留自足使用所需的摘要与步骤，不复制这些专题正文，也不自动生成缺少的专题。

## 输入与前置条件

确定仓库、README 路径和操作类型，读取项目规范及现有文档。首次生成或整体重构完整读取输出契约；局部更新只读取受影响要求。仅保存原文时核对基线和有效修正，不重新分析、扩写或启动命令验证，不新增验证声明。

## 执行流程

1. **核实入口事实**：读取现有 README、AGENTS、构建清单、主要源码入口及相关专题文档，核实定位、能力和目录。命令事实按第 3 步复用；源码或配置与文档冲突时说明差异，不自行编出替代命令。
2. **按读者任务组织**：读取 [输出契约](references/output-contract.md)，串联准备、首次使用、常用开发任务、结果和故障入口；核对已有专题的权威位置。
3. **取得权威命令**：首次生成、整体重构或调整运行/开发路径时，读取项目 `AGENTS.md` 及其声明的命令正文，取得所需命令、执行目录、前提、成功判据和清理方式。已有内容完整且无失效线索时直接复用，不要求为 README 重跑验证，也不要求证明文件由哪次技能调用生成。入口缺失时先调用 `ai-constraint-doc-authoring` 创建 `AGENTS.md`；命令缺失、验证状态不明或相关脚本/配置变化造成冲突时，调用该技能补齐或更新对应内容，再继续 README。此次衔接不要求额外生成 `CLAUDE.md`，也不因纯介绍、导航修订或仅保存而触发无关的前置文档生成。
4. **写入与联动**：从权威命令正文选择最小使用路径所需内容，保留执行条件并注明项目内来源链接。上游生成或验证受阻时继承其实际状态，不自行验证绕过，也不把未确认命令写成可用流程；可继续不依赖该缺口的内容。标题变化时修复受影响锚点，专题变化只同步摘要和导航。
5. **检查与交付**：按输出契约走读实际使用路径，运行 `scripts/validate_readme_structure.py <README-path> --custom-structure`。仅项目或用户明确采用内置骨架时省略该参数，其他固定契约单独核对。

## 核心约束

默认简体中文，保留代码、标识及项目已有英文约定；用户指定语言优先。README 描述当前有效能力，不把计划、历史流程或静态命令发现写成已实现、已验证。不输出密钥、私人账号或不可复用的本机路径。

## 产出边界与交付

产物为目标 README.md；采用输出契约的参考结构，按其中导语和导航落实文档边界。保留当前有效内容，局部更新和保存不重排无关部分。详细 AI 协作规则归 AGENTS，CLAUDE 薄入口只按需要链接。

交付文件绝对路径、变更范围、复用的项目命令来源、本次是否调用上游技能及其结果、内容校验和剩余缺口。复用既有已验证命令不等于本次重新执行，不能新增运行通过声明。

## 验证与完成标准

结构校验与内容验收分开：检查项目定位、适用最低内容、路径和链接，以及 README 的命令、参数、执行目录、前提和验证状态是否与权威来源一致；沿最小使用路径确认前置条件、步骤、成功结果和失败检查点能衔接。只保存时核对原文与确认状态，不把保存成功当作运行验证。
