# 前端复用治理

## 职责与边界

前端开发默认复用优先。任何页面、组件、交互、状态、样式或数据处理模式第二次出现时，都必须先判断是否抽取或消费复用单元。

本文维护复用判定与实施边界；[复用检查清单](references/reuse-checklist.md) 维护第二次出现判定、抽象类型和质量定级。只审核时给出证据与建议，实施授权不由审核结论自动产生。

### 边界

- 不为一次性、低风险、无稳定语义的极短代码强行抽象。
- 不创建万能组件、万能 hook 或巨大配置对象来追求表面复用。
- 不跨越项目分层、权限边界或模块所有权强行复用。
- 不因复用牺牲可读性；复用单元必须让两个以上调用点更清楚、更稳定或更易维护。

## 输入与前置条件

输入为本次页面、组件、模块或改动范围；先区分只读审核与已授权开发，再读取项目共享入口和代表性消费方。

### 必读清单

第二次出现判定、抽取类型、质量要求、共享行为、未抽取说明和定级统一维护在 [references/reuse-checklist.md](references/reuse-checklist.md)。开发与审查都读取相关部分；键盘、手势等检查按受影响能力选择，不按 App/PWA 名称整体启用。

## 执行流程

1. 确定变更范围：
   - 先确定模式：只要求检查、审核或评估时只读；要求开发、重构或修复时，在已授权范围内实施。已有授权不重复确认。
   - 用户指定页面、模块、文件、PR 或 diff 时，检查该范围及其影响到的同类实现。
   - 用户未指定范围但任务涉及前端开发时，从目标页面、组件目录、路由、设计文档、同类页面和近期改动入手。
2. 查找同类实现：
   - 读取 [references/reuse-checklist.md](references/reuse-checklist.md)，按查找入口定位同类实现。
   - 有同类实现时至少读取一个代表性页面或组件；新项目或没有同类时记录检索结果，不为满足数量创建示例。
   - 若项目有 `DESIGN.md`、组件目录、页面模板、组件库、全局样式或工具库，先读取相关入口。
3. 做复用判定：
   - 若已有复用单元能覆盖，必须消费已有入口；若已有一处相同模式，本次成为第二处，必须优先判断抽取。审核模式据此判断现状并提出建议，不执行迁移。
   - 若不抽取，必须给出理由，说明为什么不是同一变化原因、为什么抽象成本更高，或为什么当前需求不稳定。
4. 实施抽取（仅开发或已授权修复模式）：
   - 选择最低必要抽象层级：组件、hook/composable、util、schema、配置、样式、测试 helper。
   - 保持原有行为不变，先让旧使用点和新使用点都消费同一复用单元；迁移后删除被替代的重复代码和页面私有样式。
   - 抽象只承载共同变化点，保持 API 小而清楚；差异通过明确 props、slots、options、callbacks、schema 或配置传入。
5. 验证闭环：
   - 行为变化按风险补充或更新定向测试，执行项目要求的适用验证命令；不因抽取复用默认执行全量测试或构建。
   - 需要验证消费者行为或外观时，读取 [前端验证规范](~/ai-agent-config/config/force/frontend-verification.md)，按影响选择证据；本技能判断共享实现是否造成分叉。
   - 如果项目有组件清单、DESIGN 文档、页面模板或组件预览要求，按项目规则同步登记。

## 核心约束

只在同一变化原因和合适分层内复用。既有入口能覆盖时直接消费；不能抽取时记录语义、生命周期或成本依据，不用共享外壳掩盖内部重复。

## 产出边界与交付

### 输出要求

下列片段按 [文档结构与输出规范](~/ai-agent-config/config/force/document-output.md) 作为**参考结构**嵌入已有计划或审查结论；检索依据、复用或不抽取的判断，以及实施模式下的消费者迁移和验证信息不得遗漏。

组织遵循 [面向读者的组织与审阅](~/ai-agent-config/config/force/document-output.md#面向读者的组织与审阅)，以一个复用候选或共享单元为对象，关联同类实现、抽取或不抽取的依据、消费方影响及适用验证；跨对象的共同依据集中说明。审核给建议，实施报告实际迁移与验证结果，按下列适用字段表达，不为填表创建过程文档。联合审核按统一验证规范合并同根因问题。

```md
### {复用候选或共享单元}
- 现状与依据：同类实现的位置、共同变化点及差异；无同类实现时说明检索范围。
- 判断与边界：复用现有入口、扩展、新增或不抽取，以及理由、共享入口和保留的差异。
- 消费方与处理：受影响的旧、新使用点及迁移安排；实施模式补充实际接入结果和未完成项。
- 验证与维护：对应消费者的检查方式与通过条件；已执行时填写结果和证据，未执行时说明限制；关联需同步的组件清单、DESIGN 或测试及其状态。
```

按实际候选重复该单元，简短判断可合并为一段；仅审核时保留建议状态，不编造迁移或验证结果。共用检查引用一次，不另按“已复用／新增／未抽取”维护平行明细。

## 验证与完成标准

检查旧、新消费者是否消费同一入口，未抽取是否有依据，必要登记与定向验证是否完成；按执行流程核对消费者行为和外观，未实测不得声明通过。
