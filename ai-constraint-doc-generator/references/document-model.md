# AI 约束文档内容适配模型

## 用途

结构与适用性按 `output-contract.md` 决策；本文件提供不同类型的内容检查项。

只写当前有效、稳定、可执行并会改变 Agent 行为的项目事实或约束。通用常识、阶段流水、一次性故障和个人环境快照不进入项目级长期规则。

## 规则选择标准

每条内容至少满足一项：

- 告诉 Agent 应在哪里定位事实、修改代码或放置产物；
- 防止破坏正确性、安全性、权限、数据一致性、兼容性、构建产物或用户流程；
- 给出经过验证的环境、测试、构建、启动、状态检查或停止命令；
- 明确必须询问用户、禁止操作或允许自动执行的边界；
- 定义完成任务前必须通过的自审、验证和文档同步条件。

不满足上述条件的项目介绍、技术宣传、普通编程常识和重复规则不写入。

## 项目特有契约的条件内容

以下内容作为 `项目特有契约` 章节下的三级标题，按项目事实选择，并保持下列相对顺序：

1. `核心业务、数据与接口契约`
   - 领域不变量、状态流转、权限边界、数据一致性、算法口径、API 兼容和审计要求。
2. `前端设计与交互`
   - 设计事实源、组件复用、页面闭环、响应式、截图或交互验收要求。
3. `服务生命周期与端口`
   - 多进程、端口、启动、健康检查、日志、停止和测试前后状态恢复要求。
4. `外部服务与数据资源`
   - 数据库、缓存、队列、对象存储、外部 API、迁移、文件锁和降级边界。
5. `测试账号与权限验收`
   - 登录、RBAC、多租户、固定调试账号的来源和最小权限验收；不写真实密码或令牌。
6. `多语言、Monorepo 与共享包`
   - 多语言工具链、workspace、子项目边界、内部依赖和构建顺序。
7. `发布、部署与回滚`
   - 制品、镜像、CI、发布环境、配置装配、回滚和产物同步要求。

未触发的三级标题省略，不写泛泛原则。项目存在其它稳定硬契约时，归入语义最接近的小节；确实无法归类时才新增三级标题，并在交付说明中解释。

## 命令内容

`命令与验证` 按环境检查、依赖准备、测试、静态检查、构建、本地启动、状态或健康检查、停止清理的稳定顺序组织。每条命令至少写清：

- 执行目的和触发条件；
- 工作目录；
- 精确命令；
- 成功判定；
- 长期进程的停止和状态恢复方式。

命令必须通过 `verification-gate.md`。仓库没有某类命令时写明可验证事实，不编造通用替代命令。

## 规则表达

- 强制规则使用“必须”“禁止”“仅当……时”“完成前必须”等可判定表述。
- 建议性内容只有存在明确取舍时才使用，并说明触发条件；不把建议伪装成门禁。
- 规则尽量链接代码、配置、脚本或权威文档入口，不复制长篇下游内容。
- 仓库声明的运行时和工具链要求可以长期保留；本机临时版本、单次测试数量和一次性执行时间只在交付汇报中说明。
- 同一规则只保留一个权威位置，其它文档只做链接。

## CLAUDE.md 内容边界

`CLAUDE.md` 只承担 Claude Code 入口职责：

- 指向 `AGENTS.md` 和必要事实源；
- 要求改动前读取项目规则和相关实现；
- 将命令、端口、测试、服务生命周期和项目契约指回 `AGENTS.md`；
- 只有项目确实配置 Claude 记忆时才增加 `记忆边界`，并规定仓库事实优先。

不得复制 `AGENTS.md` 的完整规则、命令表、技术栈或项目介绍。

## 排除内容

- 未成功执行却被描述为日常可用的命令；
- 临时任务、迁移过程、旧决策、进度记录和已结束故障；
- 详细 README、架构、设计、需求或 API 内容；
- 密钥、凭证、私人绝对路径、完整连接串和真实账号秘密；
- 来源模板或其它项目的业务事实；
- 仅为了填充章节而写的通用规则。
