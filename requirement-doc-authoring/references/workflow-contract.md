# 需求协作共用契约

供需求闭环、正式需求、页面原型和开发计划技能读取；只维护四阶段共用的事实调研、成果继承、范围状态和交接规则，并接入通用文档规范。各阶段的执行流程、编号分配和执行状态由所属技能维护，产物结构、字段及内容验收由各自唯一模板维护。

执行时读取 [协作规则](~/ai-agent-config/config/force/collaboration-rule.md) 的授权、目录与成果覆盖要求，[文档输出规范](~/ai-agent-config/config/force/document-output.md) 的结构、裁剪和已有成果处理要求，以及 [文档边界规范](~/ai-agent-config/config/force/document-boundaries.md) 的内容归属要求；已读取的直接复用。本文不重复定义这些通用规则。

## 事实与继承

- 按用户指向、内容语义和可证明的文档关系选择当前输入及上游成果，不绑定固定文件名，也不把同目录材料自动当作上游。保存对象以用户指向成果及后续有效修正为准，多个候选无法判断时才确认。
- 围绕本次链路核实代码、页面、接口、数据、配置、权限和测试，记录影响需求或方案的来源、字段与状态。区分实现事实、已确认结论、推断和未决；代码不能单独证明业务必须如此。解释关键领域术语与口径，可核实的事实不交由用户拍板，访问受限时记录缺口。
- 继承上游功能点、入口、流程、状态、数据、权限、异常、范围、建议项状态及确认结论，不重跑已完成分析或发散平行需求。新事实与既有结论冲突时，定位依据、影响及待决选择；跨文档只保留本阶段所需摘要和追溯。
- 复用有效项目规则与同类能力，确需新增抽象时给出现有能力不足的依据；业务要求、内部实现选择和实际验证证据分别承载。

## 确认与推进

- 承接或转换上游成果时，对改变目标、范围、交付形态或既有契约的条目保留授权来源及确认状态；同时核对交付入口、保持项与允许变化。授权有效性及常规细节处理遵循协作规则，不因上游编号或标签跳过核对。
- 上游把推断写成要求，或与用户有效指令冲突时，不直接分解成下游任务；依据既有授权修正受影响条目和引用，实质选择未定则阻塞依赖部分。交付前对照用户要求及这些保持项、变化项，不只对照 AI 自己形成的文档。

| 未决类型 | 阶段处理 |
| --- | --- |
| 阻塞选择 | 缺失结论使当前成果无法成立，或实质改变范围、流程、状态、权限、数据/接口、方案或验收；说明影响、推荐及理由，等待选择后再推进依赖部分，其余工作继续。 |
| 非阻塞未决 | 不影响当前阶段成立，记录影响、确认时点和依赖；用户未答不等于同意，到达依赖点仍未解决时转为阻塞。 |

先核实事实再分类，有项目依据、低风险且可回退的常规细节自行处理，技术细节本身不构成业务确认理由；按影响分批提问，不设置机械数量。保存当前阶段草案须保留假设和未决状态，不能据此标为最终确认或启动依赖实现。当前阶段完成不自动授权下一阶段、生产开发或其他产物；阶段切换依用户请求和对应技能触发规则判断。

## 范围与交接

- “必须实现 / 建议实现 / 暂不实现”互斥，同一项只登记一次。建议项状态统一为 `本次纳入`、`后续建议`、`已实现`、`待确认`、`不纳入`；`已实现` 须有真实证据。获准纳入的建议属于本次验收范围，保留建议来源即可，不再复制成另一份必须项。
- 按当前阶段保持功能点、需求项、页面功能点、开发任务及验证项可追溯。闭环结论、正式需求契约、计划实施结果和实际验证证据各有维护位置，不混写成同一状态；写入前后核对阶段范围、确认状态和受影响引用，默认文件名由阶段技能维护。
- 识别适用的缺陷修复、重构/升级、数据迁移/补数/修复、异步/第三方、从零建设或技术验证；允许组合，按所属技能把条件要求落实到当前阶段条目及验收，不重建整套阶段材料或专项文档。只写“已考虑”不足以交接，领域口径须有项目或专项依据。
- 从零建设以目标、外部约束和已确认选择为基线，待建设与无法访问分别表达；技术验证须明确假设、边界和成功/失败判据，验证成功不等于生产可用。
- 性能、安全和兼容性均须判断；低风险在对应模板的固定字段说明依据，实质目标或风险在所属条目展开，不虚构指标或引入无必要设施。
- 首次完整形成成果或获准补全时，沿一条代表性场景连接前提、操作、反馈、数据/状态、交接与失败恢复，检查本阶段产物能否支持下一步判断。示例只解释既定规则，不新增需求或充当实现、验证证据；已有成果覆盖时直接复核，不为走读另写一份或扩写保存基线。
