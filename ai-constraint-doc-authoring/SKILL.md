# AI 约束文档编写

## 职责与边界

本技能基于目标仓库事实创建或维护项目级 AI 协作说明，不承担业务开发、部署或全局协作规范编写。

本文维护操作流程、协作边界和交付检查；[输出契约](references/output-contract.md) 维护内容取舍、产物参考结构、最低内容、项目条件内容和更新规则，[验证门禁](references/verification-gate.md) 维护命令验证及失败处理。检测和校验脚本提供辅助证据，不替代实际执行与语义核对。

使用 `AGENTS.md` 作为项目级权威入口；`CLAUDE.md` 是 Claude Code 薄入口，指向权威规则和事实源，不复制完整规则。

本技能统一维护项目命令的发现、验证与权威来源，供 `project-readme-authoring` 消费。README 技能需要的来源缺失或失效时，由本技能创建 `AGENTS.md` 或更新相关命令；已有独立权威命令文档则由 AGENTS 指向它，不另建重复正文。此次协作只补齐所需入口和事实，不反向调用 README 技能或要求 README 先完成；也不自动新增 CLAUDE。

## 输入与前置条件

确定目标仓库、用户要求的文件及操作类型：首次生成、整体重构、局部更新或仅保存已有成果，并明确本次维护的是规则/导航、命令还是两者。读取实际存在的 `AGENTS.md`、`CLAUDE.md`、`README.md`、相关设计和架构文档、包管理文件、构建文件、启动脚本与测试配置，识别有效约束、当前基线和可验证事实。专项内容由用户、项目权威文档或调用方提供事实、约束及授权边界，本技能不维护调用方的专属流程。

生成或重构前完整读取 [输出契约](references/output-contract.md)，按其中的项目条件内容选择适用主题；局部更新读取受影响规则，保留其他有效内容。判断命令验证范围和落地条件前读取 [验证门禁](references/verification-gate.md)。

只读取已检测技术栈对应的语言参考：

- [Python](references/languages/python.md)：Python、FastAPI、Django、pytest 等项目。
- [Vue / Node](references/languages/vue.md)：Vue、Vite、Node 包管理项目。
- [Java](references/languages/java.md)：Java、Maven、Gradle、Spring 项目。

缺少事实依据时先查证；无法验证的内容标明限制，不把其他项目或技能样例中的业务事实带入目标仓库。

## 执行流程

1. **确定操作与事实基线**：识别现有入口、规则优先级、事实源和文件引用。首次生成或整体重构覆盖授权范围；局部更新仅调整受影响内容，不套用整份模板。仅保存时保留所指原文及确认状态，不重新生成；保存到正式入口仍须满足适用落地门禁，未通过时按门禁提供未落地草案，不伪装成已验证规则。
2. **建立验证计划**：按验证门禁确定本次维护对象和范围；涉及项目命令时，运行 `scripts/detect_project_commands.py <repo-root>` 收集技术栈、清单文件、脚本和候选命令，核实其确属目标项目后确定精确命令、工作目录、成功判定、清理方式及落地必验项。仅维护规则/导航时核对事实来源、授权边界、链接和文档结构，不扩展为无关命令验证；候选扫描不能代替执行验证。
3. **执行适用门禁**：核对仓库声明的运行时要求，并实际验证将写入的环境检查、依赖或工具可用性检查、测试、构建、本地启动、状态检查和停止命令。优先使用仓库封装的生命周期脚本。必验失败时不写入或覆盖正式入口；仅有明确、非破坏性修复依据时定向重试一次，仍失败或原因不确定时按验证门禁停止依赖操作并请求处理选择，不连续试错。已有授权与适用的更高优先级规则继续有效。
4. **形成授权范围内的成果**：门禁通过后起草或更新，仅将成功执行的命令列为已验证流程；其他已发现命令明确标注为不属于已验证流程。按输出契约保留稳定规则的主题入口，将场景专属依据、验证与同步要求就近组织，保存和局部更新不借机扩写或重排。
5. **落地并复核**：在授权范围写入目标文件，重读并执行下述验证与完成标准。汇报写入文件、实际验证结果和剩余限制。

## 核心约束

- 从当前仓库事实生成面向 AI 的说明，只保留当前有效、稳定可执行、会影响后续协作质量的规则，不凭记忆或照搬样例。
- 区分规范与实现事实：有效项目规范和用户要求决定应遵守的约束；代码、脚本和机器配置用于核实当前实现与运行方式。发现冲突时记录差异，按适用规则优先级处理，不因现有实现不同而覆盖有效规范；影响正确性且无法消解时暂停依赖该结论的操作。
- 项目特有契约只保留会影响正确性、安全性、数据一致性、权限、构建产物或用户流程的内容。重构时清除过期迁移说明、历史流水、临时案例、猜测命令和重复规则；局部更新不清理授权范围外的内容。
- 不把已发现但未验证的命令描述为可直接执行的日常流程；必验失败不得绕过门禁落地正式入口。
- 除命令、代码、文件名、机器字段和目标仓库已有英文约定外，默认使用简体中文；用户明确要求英文时采用英文。
- 入口必须使后续 Agent 能定位需求、设计、架构、开发调试和部署事实源，并知道何时读取。只有目录名而无用途说明不算有效导航；不存在的资料不能编造入口。
- AGENTS/CLAUDE 保留约束与触发条件，面向人的操作细节归入 README 或专门指南，不把“薄入口”原则扩展到所有文档。

## 产出边界与交付

在用户指定的项目范围创建或更新 `AGENTS.md`、`CLAUDE.md`；只请求其中一份时不自动新增另一份，涉及另一份的同步缺口在交付中说明。产物采用输出契约的**参考结构**，技能正文的六类主题不作为项目文档的固定模板。

按 [全局文档边界规范](~/ai-agent-config/config/force/document-boundaries.md) 将以下分工落实到首次生成或获准补全的产物中；复用已有用途或范围说明，CLAUDE 薄入口可合并到权威规则入口。仅保存、逐字保存或局部更新时不为补边界扩写或重排，范围外缺口在交付中报告；这不免除正式入口的命令验证门禁。

- `AGENTS.md`：维护所有 AI Agent 的项目级协作规则。
- `CLAUDE.md`：只保留 Claude Code 入口指引、工作方式和适用的稳定记忆规则。
- `README.md`：产品或开发概览，作为事实源引用，不将 AI 协作规则复制进去。
- 设计、架构、需求及功能文档：沿用既有职责并引用入口，不复制完整细则，也不因生成 AI 入口而自动创建这些文档。

交付说明已写文件、按技术栈分组的已验证命令、未写入命令及原因、未覆盖项和残余风险。门禁失败时按验证门禁报告证据与未落地状态，不声称完成正式文档交付。

## 验证与完成标准

- 写入前确认适用命令门禁通过；写入后重读文件，核对规则归属、命令及其验证状态、事实来源和是否混入样例项目内容。
- 检查入口能否引导后续 Agent 定位并选择事实源，检查链接及受标题变化影响的仓库内锚点；局部更新核对原有有效信息和确认状态没有被扩大或覆盖。
- 运行 `scripts/validate_ai_constraint_docs.py <repo-root> --custom-structure --document <agents|claude|both>`，按本次交付范围选择文件；省略 `--document` 时兼容原有双文件校验，所选文件缺失仍报错，不为通过检查新增未授权文件。默认用 `--custom-structure` 检查正文、空章节、占位内容和 CLAUDE 薄入口边界，不要求二级标题；只有明确采用内置骨架时才省略该参数并检查固定标题与顺序。外部固定契约和最低内容另行核对。
- 分别报告命令执行证据与文档校验结果；失败或必要验证未完成时保留实际状态，不宣称验收通过。
- 单文件校验不代表另一份已通过；CLAUDE 指向的权威入口及其他事实源仍按链接检查核实，缺失或失效时报告缺口，不自动补建。
