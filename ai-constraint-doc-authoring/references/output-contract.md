# AI 约束文档输出契约

生成前读取 [共用声明骨架](~/ai-agent-config/config/force/document-boundaries.md#共用声明骨架)，在下方适用范围或权威规则入口落实具体职责及权威位置；已有等价说明直接复用。

## 适用规则

结构策略为**参考结构**，按 [模板与结构选择](~/ai-agent-config/config/force/document-output.md#模板与结构选择) 组织及维护已有成果。适用最低内容、入口职责和必要固定项见下文；不得因调整章节而丢失执行约束。

## 内容选择与表达

只写当前有效、稳定、可执行并会改变 Agent 行为的项目事实或约束。每条内容至少服务于事实/代码/产物定位、正确性与安全等项目契约、已验证操作、授权边界或完成判断；不填充技术宣传、普通编程常识和无关原则。

- 强制规则使用“必须”“禁止”“仅当……时”“完成前必须”等可判定表述；建议须有明确取舍和触发条件，不伪装成门禁。
- 链接代码、配置、脚本或权威文档入口，不复制详细 README、架构、设计、需求或 API 正文；同一规则只保留一个权威位置。
- 仓库声明的运行时和工具链要求可以长期保留；本机实测版本、单次测试数量和一次性执行时间只在交付汇报中说明，不写入长期规则。
- 不写临时任务、迁移过程、旧决策、进度记录和已结束故障；不带入其他项目或模板的业务事实。
- 不写密钥、凭证、真实账号秘密、完整连接串或私人绝对路径。

## AGENTS.md 参考章节

一级标题使用项目名称或“项目 AI 协作说明”。以下主题提供参考结构，适用内容必须覆盖，可合并章节：

```markdown
# {项目名称} AI 协作说明

## 适用范围与权威入口

用途与归属：本文维护{实际目录范围}内所有 AI Agent 的项目协作规则及已验证命令的权威入口；README 从此处或所指命令正文获取操作所需内容，不独立维护命令定义；产品与操作说明、设计、架构及需求事实沿用{已有权威入口或当前归属}，仅引用执行所需内容。

## 项目事实与共用契约
## 场景专属要求
### {有专属规则的变更场景}
## 共用命令与交付检查
```

稳定契约按主题保留检索入口，存在专属规则的变更场景再就近串联执行要求，遵循 [面向读者的组织与审阅](~/ai-agent-config/config/force/document-output.md#面向读者的组织与审阅)：每个场景就近说明触发条件、要读的规则/事实入口、可改与禁改边界、必要确认、实现契约、验证方式及文档同步目标。数据变更、接口调整或页面修改只在项目实际存在相关规则时建项，不填充通用编程常识。

优先级和权威来源在入口说明；跨场景的业务/数据/API 不变量、分层、权限、安全边界与目录导航在共用契约中维护。场景只引用并补差异，不将同一接口或数据规则复制到多个场景；没有场景专属要求时省略场景章节。公用命令表保留目的/触发条件、工作目录、命令、成功判定、清理或恢复；场景引用具体命令用途。完成标准集中承载交付检查，场景只补差异，不把同一规则分别复制到安全、实现、同步等章节。CLAUDE 仍是薄入口。

下列主题用于核对内容完整性，不要求各自成章；没有额外项目契约时不创建空槽位。

## AGENTS.md 各主题最低内容

### 文档职责、适用范围与规则优先级

至少写明：

- 本文件约束的目录范围；
- 是否存在更深层 `AGENTS.md`，以及就近规则的覆盖关系；
- 用户明确要求、项目级规则和上级通用规则的优先关系；
- 代码、机器配置、README、架构、设计、需求等事实源发生冲突时如何处理。

### 项目事实与代码结构

至少写明项目用途、主要交付形态、关键源码/测试/配置/脚本/文档目录及职责。标出生成物、第三方代码、缓存、构建产物和默认禁止修改的区域。只写影响定位和变更的事实，不复述完整产品介绍。

### 变更边界与实现约束

至少规定：

- 修改前如何寻找同类实现和权威事实；
- 需要保持的分层、命名、API、数据、权限、错误处理或配置方式；
- 新增依赖、公共抽象、生成代码和跨模块改动的边界；
- 何种技术方案、交互或业务规则必须先确认。

规则必须来自当前项目，不复制与项目无关的通用开发口号。

### 命令与验证

按环境、依赖、测试、静态检查、构建、本地启动、状态或健康检查、停止清理的稳定顺序组织。推荐使用表格：

| 目的/触发条件 | 工作目录 | 已验证命令 | 成功判定 | 清理或恢复 |
|---|---|---|---|---|

命令正文默认在 AGENTS 维护；项目已有独立权威命令文档时引用其具体位置，并在该正文补齐同等信息，不能新建第二张完整命令表。README 可按读者路径展示必要命令片段并链接来源，命令或执行条件变化时先维护权威正文再同步引用。已有 README 只能提供发现线索，不能以其自身声明替代执行证据。

所有作为日常流程写入的命令必须通过 `verification-gate.md`；任一落地必验命令失败时，不覆盖 `AGENTS.md` 或 `CLAUDE.md`。长期服务必须包含启动、就绪判断和停止闭环。

### 项目特有契约

至少覆盖会影响正确性、安全性、权限、数据一致性、兼容性、服务生命周期、构建产物或发布结果的现有契约。规则写清触发条件、必须动作或禁止动作，以及可复核的事实入口。按项目事实选择下列条件内容，不固定标题或顺序；共用规则按主题维护，场景专属规则就近表达：

1. `核心业务、数据与接口契约`
   - 领域不变量、状态流转、权限边界、数据一致性、算法口径、API 兼容和审计要求。
2. `前端设计与交互`
   - 设计事实源、组件复用、页面闭环、响应式、截图或交互验收要求。
3. `服务生命周期与端口`
   - 多进程、端口、启动、健康检查、日志、停止和测试前后状态恢复要求。
4. `外部服务与数据资源`
   - 数据库、缓存、队列、对象存储、外部 API、迁移、文件锁和降级边界。
5. `测试账号与权限验收`
   - 登录、RBAC、多租户、固定调试账号的来源和最小权限验收；不写真实密码或令牌。
6. `多语言、Monorepo 与共享包`
   - 多语言工具链、workspace、子项目边界、内部依赖和构建顺序。
7. `发布、部署与回滚`
   - 制品、镜像、CI、发布环境、配置装配、回滚和产物同步要求。

未触发的内容省略，不写泛泛原则。其它稳定硬契约按职责放入对应主题或场景，不为匹配清单强制增设章节。

### 文档与产物同步

至少写明：

- 什么改动会触发 README、架构、设计、API、需求、部署或 AI 规则更新；
- 项目产物目录规则引用全局协作规则，仅补充项目特例；
- 同一事实的权威位置和其它文档的引用方式；
- 完成改动后必须检查哪些事实文档是否需要同步。

没有项目特例时，沿用全局协作规则“建文档目录时”，不重复维护通用目录规则。

### 安全、确认门禁与禁止操作

至少覆盖与项目实际相关的凭证、生产或外部系统写入、数据库变更、破坏性文件/Git 操作、依赖安装、长任务和用户确认边界。明确哪些行为可自动执行、哪些必须先确认、哪些始终禁止。不得写入真实秘密。

### 完成标准

至少包含：

- 以第三方视角自审本次改动并修复发现的问题；
- 检查同类位置是否存在相同问题或受影响能力；
- 按风险执行已验证的最低充分测试、构建或运行检查；
- 检查文档和规范是否需要同步；
- 汇报变更文件、验证命令、未覆盖项和残余风险。

## CLAUDE.md 参考结构

`CLAUDE.md` 是薄入口，默认使用：

```markdown
# Claude Code 项目入口

## 权威规则入口

本文仅提供 Claude Code 项目入口指引；共用协作规则以{实际 AGENTS.md 路径及链接}为准，命令和专题事实从其声明的入口读取。

## 工作方式
## 记忆边界
```

必须说明权威规则入口和工作方式，可合并为一节；记忆边界仅在项目存在相应策略时写入。保持薄入口，不复制 AGENTS.md 正文。

最低内容：

- `权威规则入口`：明确仓库协作规则以 `AGENTS.md` 为准，并链接必要事实源；
- `工作方式`：要求改动前阅读 `AGENTS.md` 和相关实现，将命令、测试、端口和项目契约指回 `AGENTS.md`；
- `记忆边界`：只写稳定记忆规则，并明确仓库当前代码和文档优先于外部记忆。

`CLAUDE.md` 不复制命令块、完整项目规则、技术栈和长篇项目说明。

## 更新已有文档

- 保留仍有效的项目特有规则和命令；不能为了套骨架删除安全、业务、数据或发布约束。
- 局部更新沿用原有标题和层级；重构时按阅读顺序组织，避免重复定义。
- 合并重复规则，`AGENTS.md` 保留权威正文，`CLAUDE.md` 和其它入口仅链接。
- 删除历史流水、临时案例、本机环境快照、过期命令和没有事实依据的规则。
- 重构标题前后检查仓库内引用和锚点，必要时同步更新。

| 记忆边界 | Memory Boundaries |

英文 `CLAUDE.md` 一级标题使用 `# Claude Code Project Entry`。

## 交付门禁

落地前必须确认：

- 适用的规则、命令、边界和完成要求有明确承载，无重复或无依据的填充；
- `CLAUDE.md` 保持薄入口且没有复制命令块；
- 命令验证门禁已经通过；
- 文档链接和受标题调整影响的仓库内锚点有效；
- 已按 [技能入口的校验方式](../SKILL.md#验证与完成标准) 对本次交付文件执行结构校验并通过；单文件交付不要求另一份同时存在，但引用目标仍须核实。脚本只验证结构，最低内容必须语义复核。
